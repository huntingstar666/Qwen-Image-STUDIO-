# 定格工坊（still_loop）业务流程与手动操作说明

> 本文档描述 still_loop 的业务链路、所需服务、每类项目的操作方式，以及单帧「AI 精修」的参考图与手动参数规则。
> 前端所有按钮都能在这份文档里找到对应的接口与依赖服务。

---

## 1. 服务依赖

| 服务 | 地址 | 用途 | 是否必需 |
| --- | --- | --- | --- |
| 定格工坊 still_loop | `http://127.0.0.1:8720` | 编排、审核、导出、状态机、页面 | 必需 |
| 主项目（Qwen-Image Studio） | `http://127.0.0.1:8700` | `/api/upload` 上传、`/api/edit` 提交编辑、`/api/jobs/{id}` 轮询，底层走 ComfyUI 出图 | AI 精修 / 连续编辑生成时必需 |
| 动画稳定化 | `http://127.0.0.1:8710` | 导出 GIF 时的去抖动、去闪烁 | 可选，勾选才调用 |
| Ollama LLM | `http://127.0.0.1:11434` | **仅**「连续编辑」的 LLM 分镜：一句话想法 → 逐帧提示词 | 可选，只影响 LLM 分镜 |

结论先说清楚：

- **「AI 精修」不需要 LLM。** 它只是把「原图 + 提示词 + 采样参数」提交给主项目 `/api/edit`，由 ComfyUI 的 Qwen-Image 编辑模型出图。
- LLM 只在一处出现：连续编辑里选「LLM 分镜」时，把一句话想法拆成逐帧提示词。手写分镜则完全不碰 LLM。
- 照片轨道、宫格切分、自动化流水线、导出成片，都不依赖 LLM。

## 2. 四类项目（run）的流程

### 2.1 照片轨道（`source = photos`）

1. 选素材：页面上传照片，或从主项目素材仓库多选（两者互斥，切换前会确认）。
2. 创建：`POST /api/loop/runs/import-photos`（本地文件）或 `/runs/from-materials`（素材 id）。
3. 首轮结果：每张照片直接成为一帧原图，状态 `accepted`（不经过 AI）。
4. 手动可做：改提示词、AI 精修单帧、调停格、前移/后移、删除、恢复原图。
5. 导出：GIF / WebP / MP4 / WebM，顺滑版 + 定格版。

服务：创建与导出不需要 8700；**只有 AI 精修**需要 8700。

### 2.2 宫格切分（`source = sheet`）

1. 上传一张宫格图。
2. `POST /api/loop/runs/sheet` 切分，按行优先 / 蛇形 / 列优先铺入轨道。
3. 每格是原图，可逐格 AI 精修。
4. 导出同上。

### 2.3 自动化流水线（`source = pipeline`，实验性）

1. 上传宫格图，设定行列、间隔、读取顺序、裁边。
2. `POST /api/loop/runs/pipeline`：先切分，再按统一提示词逐格 AI 精修。
3. 自动化结果不稳定，允许逐格手动：改词 → 只重跑该格；恢复原图；删除；重排。
4. 导出同上。

服务：切分不需要 8700；精修需要 8700。

### 2.4 连续编辑（`source = chain`）

1. 上传参考图。
2. 二选一分镜方式：
   - **LLM 分镜**：一句话想法 → `POST /api/loop/runs`（planning），由 Ollama 生成逐帧提示词。
   - **手写分镜**：每行一条提示词，直接用，不调用任何模型。
3. 逐帧接力生成：第 N 帧以第 N-1 帧为输入继续画，保证动作连贯（`/runs/{id}/start`）。
4. 重试语义不同：重试第 N 帧会**作废 N 之后的帧**，因为它们依赖前面的结果。
5. 导出同上。

服务：LLM 分镜需要 11434；生成需要 8700。

## 3. 单帧生成 / 精修（本次重点）

### 3.1 输入从哪里来：参考图框

检查器里是一个**参考图框**，用户自己决定这次生成用什么图：

- **从轨道拖帧进框**：想拖几张拖几张，按拖入顺序排列；拖进来时提示词里会自动补一个 `@帧N`。
- 把图移出参考框时，提示词里对应的 `@帧N` 会一并删掉，不会在提交时被自动加回来。
- **框内第一张是画布**（被编辑的图），其余是参考图。
- **框空着就是文生图**：只把提示词发给 8700 `/api/generate`。
- **框里有图就是图生图**：提交给 8700 `/api/edit`，`images[0]` 是画布，`images[1..]` 是参考。
- 每张图右上角可以移出；把一张图拖到另一张上可以调整顺序（顺序决定 `<image1>`、`<image2>`）。
- 默认值：照片 / 宫格 / 流水线把**本帧**放进画布；连续编辑由接力流程用**上一帧**当输入。
- 框里的图取「已通过结果 > 当前结果 > 原图」，和轨道上看到的缩略图一致。

主项目协议：`images[0]` 一定是画布，后面才是参考图。所以「上一帧当参考」= 把上一帧拖进框里排第二张；「上一帧当画布」= 把上一帧拖成第一张。

### 3.2 手动参数

单帧精修时可以临时覆盖采样参数，**不写回轨道设置**：

- 步数 `steps`
- CFG `cfg`
- 降噪 `denoise`
- 随机种子 `seed`（-1 表示随机）

留空即沿用轨道创建时的设置。

注意主项目的 Turbo 档位会强制 8 步 / CFG 1.0。因此**只要手动填了步数或 CFG，本次精修会自动关闭 Turbo**，否则这两个值会被预设静默覆盖；只改种子或降噪则保持 Turbo 不变。

### 3.3 提示词与 @ 引用

- 在提示词里输入 `@` 会列出轨道上可用的帧；选中后插入 `@帧N`，**该帧自动进入参考图框**。
- 提交时 `@帧N` 会按参考框顺序替换成 `<image1>`、`<image2>`…，与主项目协议一致。
- 只写 `@帧N`、没写别的也可以；但文生图（框为空）必须写提示词。
- 文本框内容会随请求提交，并写回该帧，便于下次继续用。
- 留空时使用内置兜底提示词：**只统一质感、不改内容**（框里有图时）。
- 生成只作用于当前帧；照片轨道 / 宫格 / 流水线三类互不影响。

### 3.4 调用链

```
检查器「生成这一帧」
  → POST /api/loop/runs/{id}/frames/{n}/retry
     body: { prompt, images: [3, 2, 1], settings: {steps,cfg,denoise,seed} }
     images[0] 是画布，后面是参考图；空数组 = 文生图
  → runner.retry_frame → _edit_single_frame
  → 有图：8700 POST /api/upload（画布 + 每张参考各一次）
         8700 POST /api/edit（images[0]=画布，images[1..]=参考）
  → 无图：8700 POST /api/generate（文生图）
  → 轮询 /api/jobs/{id} → 下载结果 → 写帧 + 生成 report
```

全程不经过 LLM。

### 3.5 失败处理

- 按「单帧重试次数」重试；每次失败都记入该帧 attempts。
- 全部失败：该帧 `blocked`，项目 `blocked`，不阻断其它帧的手动操作。
- 8700 任务被取消：抛 `GeneratorCanceled`，项目回到可操作状态。

## 4. 手动操作矩阵

| 操作 | 位置 | 调用 | 依赖 |
| --- | --- | --- | --- |
| 保存提示词 | 检查器 | `PATCH /runs/{id}/frames/{n}` | 无 |
| 生成这一帧（图生图 / 文生图） | 检查器参考框 + 提示词 | `POST /runs/{id}/frames/{n}/retry`（带 `images`） | 8700 |
| 恢复原图 | 检查器 | `POST /runs/{id}/frames/{n}/restore` | 无 |
| 前移 / 后移 | 检查器 | `POST /runs/{id}/frames/order` | 无 |
| 删除帧 | 检查器 | `DELETE /runs/{id}/frames/{n}` | 无 |
| 批量精修 | 左栏 | `POST /runs/{id}/pipeline` | 8700 |
| 改停格 | 左栏 / 轨道卡 | `PATCH /runs/{id}/timeline` | 无 |
| 播放预览 | 播放器 | 纯前端 | 无 |
| 导出成片 | 右栏「导出」 | `POST /runs/{id}/export` | 可选 8710 |
| 删除项目 | 我的项目 | `DELETE /runs/{id}` | 无 |

审核说明：当前没有独立的「逐帧通过/驳回」按钮。审核动作就是**在预览与检查器里确认**，点「导出成片」时前端会先调 `POST /runs/{id}/approve`（失败也不阻断导出）。

## 5. 状态机

```
draft → planning → planned → running → review ─┬→ exporting → done
                                      └→ blocked（有帧失败/待人工）
running → canceled（用户取消）
任意   → failed（不可恢复错误）
```

帧状态：`pending → running → accepted | blocked | retrying`，`blocked` 只能通过重跑或恢复原图回到可用状态。

---

## 6. 导出

- 版本：顺滑版（按播放帧率）与定格版（叠加抖动/颗粒/暗角，可接 8710 去抖/去闪）。
- 容器：GIF / WebP / MP4 / WebM，按「导出格式」下拉选择。
- 时长估算：逐帧停格 ÷ 帧率累加，改动帧率或停格都会实时更新。
- 导出成功后在「导出」页列出产物，可直接预览或下载。

---

## 7. 播放器约定

- 播放 / 暂停是同一个按钮；播放期间只更新图片、角标、进度点与元信息，**不重建按钮 DOM**，避免点击被吞。
- 播放按每帧停格时长推进，到末帧回到第 1 帧循环。
- 播放中点击进度点直接跳到该帧并继续播放。

---

## 8. 已知限制

- 自定义上传「第三张参考图」暂未开放，当前只有原图 / 上一帧两种策略。
- 连续编辑的接力重试会作废后续帧，这是链路依赖决定的，不是 bug。
- 单帧精修会占用 8700 的生成队列，批量精修时请先小批量试跑。
