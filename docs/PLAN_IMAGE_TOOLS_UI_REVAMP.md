## 2. 功能检查结果

### 2.1 P0：阻断上线

#### F-01 应用裁剪后会二次裁切，保存结果小于预览

**复现**

1. 载入 941×1672 图片；
2. 选择 `1:1`，点「应用裁剪」；
3. 状态栏变为 847×846，但「裁剪输出」立即显示 761×762；
4. 直接点「处理并保存」，结果卡为 **761×762**。

**证据**

- 应用裁剪后状态栏：`847 × 846`；画布 header 仍显示源图 `941 × 1,672`（header 与状态栏口径也不一致）；
- 「裁剪输出」：`761 × 762`；
- 结果卡：`761×762`；
- 操作史：`01 裁剪 847×846`。

**根因**

- `resetCrop()` 在裁剪后按当前比例重新生成一个 **90% 居中框**（`centeredCrop(display, ratio, 0.9)`），而不是“整张新图”；
- `currentOpsForServer()` / `processAndSave()` 又无条件把 `pendingCropPixelRect()` 拼进 ops；
- 于是“已应用的裁剪”和“仍在框里的 90% 裁剪”被叠加执行两次。

相关代码：`imageTools.js:1447-1456`、`1771-1789`、`2043-2060`、`3036-3052`。

**影响**

- 用户每保存一次就损失约 10% 边缘画面；
- 正方形测试图会掩盖该问题（旧自检 512×512 → 414×414 实际就是二次裁切），必须用非正方形图回归。

**整改方向**

1. 把「已应用操作」与「待应用裁剪」彻底分开：裁剪只有点击「应用裁剪」才进入 ops；
2. 应用裁剪后选框重置为**整张新图**，比例切回 `Free`，或明确显示“已应用裁剪，当前无待应用框”；
3. 保存时只提交已应用的 ops；如存在待应用裁剪，必须在保存按钮旁显式提示“还将应用 1 个裁剪”，由用户确认；
4. 回归用例：941×1672 图，1:1 裁切后画布与保存结果必须完全一致。

#### F-02 工具轨切换后目标面板默认折叠，点击后看到空白

**复现**

- 打开页面，依次点击左侧工具轨的「水印 / 动图 / 放大 / 导出 / 扩图 / 反推」；
- 右侧「工具」区只剩一行折叠标题，下面是空的，再往下是「送入图生图」和「处理提示」。

**证据**

- 8 个工具组中只有 `adjust` 的「裁剪 / 宫格」带 `open`；
- 程序检查结果：切换后唯一可见折叠区的 `open` 为 `false`；
- 截图 `audit-02-watermark-collapsed.png` 中，点击「水印」后面板内没有内容。

**根因**

- 工具轨只做了 `.tool-fold[hidden]` 的显隐（`syncToolGroups()`），没有展开当前折叠区；
- 每个工具又额外套了一层 `<details>`，导致“点工具轨 → 再点折叠标题”两次操作。

相关代码：`imageTools.js:392-415`、`444-824`、`1121-1136`。

**影响**

- 用户会认为工具坏了或没加载；
- 新用户无法发现水印、GIF、放大等能力；
- 这是“交互质量差”的第一观感来源。

**整改方向**

1. 工具轨是**模式切换**，不是折叠面板开关：切到某工具时，参数区直接渲染该工具；
2. 取消工具参数外层的 `<details>`；仅“高级参数”保留折叠；
3. 保留 `Enter`/方向键在工具轨内切换；
4. 验收：任一工具点击 1 次后，参数区必须可见，不允许出现空面板。

#### F-03 保存入口隐藏，宫格保存复用导出按钮状态

**复现**

1. 在「调整」里完成裁剪，想保存时右侧没有保存按钮；
2. 需要切到「导出」→ 再展开「格式导出」→ 才能看到「处理并保存」；
3. 点「宫格切分并保存」时，`processAndSave()` 把 `refs.processApply` 设为 loading，宫格按钮本身不进入 loading。

**证据**

- 「处理并保存」只存在于 `data-group="export"` 的折叠区；
- `processAndSave()` 固定操作 `refs.processApply`（`imageTools.js:3038-3041`）；
- 宫格入口 `applyGrid()` 调用同一个函数（`2085-2086`）。

**影响**

- 核心动作“保存”不可预期；
- 用户在裁剪面板里看不到结果去向；
- 宫格可被重复点击，产生重复任务/重复结果。

**整改方向**

1. 页面级常驻主按钮「导出」：无论当前在哪个工具，都能打开导出面板/弹层；
2. 每个异步动作使用自己的按钮 loading 与禁用态；
3. 保存完成后在结果条高亮新增项，并提供“查看/送入编辑”；
4. 快捷键 `Ctrl/Cmd + S` 打开导出。

#### F-04 页面级滚动 + 结果条首屏不可见 + Inspector sticky 失效

**实测数据（1600×950）**

| 元素 | 数值 |
|---|---|
| 文档滚动高度 | 1156px（视口 950px） |
| 画布舞台 | 838×530 |
| 画布实际显示 | 262×466（28%） |
| Inspector | 340×926，内容高 1080 |
| 结果条 | top 836，bottom 1044 |
| 顶栏 | 72px |

**滚动 200px 后**

- Inspector `top = -82`，`bottom = 844`；
- 顶栏 `bottom = 72`；
- 也就是说 Inspector 顶部 154px 被顶栏遮住，`position: sticky` 没有生效。

**根因**

- `.tools-layout` 的高度由内容撑开，Inspector 所在 grid 区域高度等于它自身高度，sticky 没有可粘的滚动区间；
- `.tools-inspector` 的 `top: 8px` 没有把 72px 顶栏算进去；
- `max-height: calc(100vh - 24px)` 同样没有扣除顶栏与页面内边距，底部 90px 超出视口；
- 结果条在 `.tools-main` 之后、inspector 之前，属于普通文档流，必然被推到首屏之外。

相关代码：`tools.css:15-24`、`88-99`、`282-294`、`438-575`；`imageTools.js:837-891`。

**影响**

- 想看结果必须滚页面，滚动后工具区标题与源图消失；
- 用户同时面对“页面滚动 + Inspector 内部滚动”两层滚动；
- 1280×800 下结果条 top=750，卡片的缩略图与操作都在首屏外；
- 这是工作台类产品最不该出现的问题：**画布、参数、结果三者不能同时看见**。

**整改方向**

- 工作区改为“应用内固定高度”布局：`height = 100dvh - 顶栏`，`overflow: hidden`；
- 三栏各自滚动，页面不滚动；
- 结果胶片条固定在画布列底部（建议 112px），始终可见；
- Inspector 顶部对齐工作区顶部，不写死 `top: 8px`；
- 验收：1600×950 与 1280×800 下，结果条完整可见，页面无纵向滚动。

### 2.2 P1：商业化基线缺口

#### F-05 裁剪比例不精确

**实测**

| 选择比例 | 「裁剪输出」 |
|---|---|
| 1:1 | 847 × 846 |
| 16:9 | 847 × 476 |
| 9:16 | 847 × 1,504 |
| 4:3 | 847 × 634 |

1:1 不是正方形，4:3 的高度也与 847/4×3=635.25 不符。

**根因**

- 显示画布 262×466 与源图 941×1672 的横纵缩放比不一致（3.5916 vs 3.5879）；
- `cropOutputRects()` 分别用 xScale/yScale 独立取整，误差在两次方向上都保留下来；
- 比例框本身是浮点，最终 start/end 分别 `Math.round`。

相关代码：`web/vendor/image-tools-kit/src/cropGeometry.js:141-156`；`imageTools.js:1771-1789`。

**整改方向**

- 裁剪输出以“源图像素”为唯一坐标系：先按统一 scale 求整数宽高，再按比例修正另一边（例如 1:1 强制 `height = width`）；
- 比例选择后显示“精确输出 1:1：846×846”，避免用户以为只是近似；
- 增加单元测试：对 941×1672、1000×1001、4000×3000 等非方形图，所有比例输出必须满足 `abs(w/h - ratio) <= 1px`。

#### F-06 WebP 质量滑杆被隐藏，体积估算按 PNG 口径

**实测**

- 切到 WebP、未勾选无损：`qualityField` 仍然是 hidden；
- 「预计体积」显示 `≈ 2.03 MB（WEBP）`，该数值不随格式/质量变化，实际是按 PNG 口径算的。

**根因**

- `syncExportUi()` 的判断是“png 或 webp+lossless 隐藏质量”，逻辑正确；
- 但每次 render 都会跑 `updateEstimate()`，它用 `state.format !== 'jpeg'` 隐藏质量滑杆（`1819-1829`），把 WebP 又关掉了；
- 估算公式只有 JPEG 与“其它”两档，WebP 被当成 PNG 的 `1.35 bytes/px` 估算。

**整改方向**

1. 导出 UI 状态只保留一个同步函数，禁止 `updateEstimate()` 改可见性；
2. 质量滑杆：JPEG 显示；WebP 无损时隐藏、有损时显示；PNG 隐藏；
3. 体积估算按格式分档，或直接调用后端估算接口；文案改为“估算值，实际以导出为准”。

#### F-07 缩放“锁定比例”使用原图比例，不是当前画布比例

**根因**

- `bindResizeInput()` 用 `state.source.width / state.source.height` 计算比例（`2186-2202`）；
- 裁剪、旋转后当前画布已经是 847×846，输入宽度 1000 时高度仍按 941/1672 算成约 1777。

**整改方向**

- 使用 `currentWorkDims` 的宽高比；
- 旋转 90° 后同步交换比例；
- 输入框旁显示“当前比例 1:1”，让用户知道锁定依据。

---

#### F-08 放大 / 扩图 / 反推 / GIF 使用的是原图，不是当前编辑结果

**实测与代码**

- 高清放大：`api.upscale({ image: state.source.dataUrl })`（`2387-2391`），完全忽略 `stagedOps`；
- 扩图：`planOutpaint({ srcDataUrl: state.source.dataUrl, width: currentWorkDims.width, height: currentWorkDims.height })`（`3436-3449`），用原图数据 + 裁剪后的尺寸，宽高不匹配，画布与源图会被拉伸；
- 反推、「当前源图入帧」使用原图，语义上可以接受，但界面没有说明“用的是原始源图”；
- 水印使用 `currentOpsForServer()`，与放大/扩图不一致；若此时有扩图预览，水印仍基于原图 + ops，而不是扩图画布。

**影响**

- 用户先裁剪再放大，得到的是原图放大，不是裁剪结果；
- 扩图在裁剪后规划会出现尺寸错位；
- 同一页面里不同工具对“当前图像”的定义不一致，是典型的信任问题。

**整改方向**

1. 定义唯一的 `currentImage()`：原图 + 已应用 ops（必要时用后端 `process` 落一张临时图）；
2. 所有工具明确标注输入：`当前编辑结果` 或 `原始源图`；
3. 扩图规划必须让 `src` 的像素尺寸与传入 `width/height` 一致；
4. 增加“使用当前编辑结果 / 使用原图”切换（默认当前结果）。

#### F-09 画布缺少缩放、平移、前后对比、透明棋盘

**实测**

- 941×1672 图在 1600×950 下显示 28%，在 1280×800 下显示 23%；没有缩放入口，无法 100% 检查细节；
- 没有平移；超出舞台时只能看全部，不能放大局部；
- 只有高清放大后有「图像对比」，普通裁剪/调色没有前后对比；
- PNG 透明区域显示为画布底色（浅色主题为白色），没有透明棋盘。

**影响**

- “图像处理”最核心的精细操作无法完成；
- 用户无法确认锐化、噪点、边缘等细节；
- 透明素材的预览与实际导出不一致。

相关代码：`.tool-canvas` 背景 `theme.css:583-585`；舞台渲染 `imageTools.js:1434-1600`。

**整改方向**

- 画布工具栏：适应、100%、−、百分比、+、对比、棋盘/背景、重置视图；
- 滚轮以指针为中心缩放，空格/中键平移，双击切换适应/100%；
- 前后对比用可拖分割线，支持按住 `\` 临时看原图；
- 透明图使用棋盘背景，导出前可切换背景色。

---

#### F-10 无草稿保护：刷新、离开、清空都可能丢失工作

**现状**

- 源图、ops、结果全部在页面闭包内，刷新即丢失；
- 没有 `beforeunload` 提示；
- 「清空」结果、「重置」全部操作都没有二次确认；
- 结果只存在于内存，切页保留，刷新不保留。

**整改方向**

- 本地草稿：IndexedDB 保存源图（或文件引用）、ops、结果元数据、当前工具与缩放；
- 页面重进时提示“恢复上次未完成的工作”；
- 有未导出结果时离开页面给出确认；
- 「清空结果」「重置」使用危险操作确认，并提供撤销 toast。

---

#### F-11 1100px 断点把 Inspector 排到结果条之后

**实测（1100×800）**

- 进入单列布局：工具轨 → 画布 → 操作史 → 结果 → Inspector；
- 画布舞台 772×350，图片 286×286（34%）；
- 结果条 top=710，首屏未完整显示；
- 顶栏标题换行/截断。

**影响**

- 在 1024–1180 的笔记本/平板上，要改参数必须先滚过画布、操作史、结果，交互路径极长；
- 与 `PLAN_IMAGE_TOOLS_V2.md` §8.4 “<1100 Inspector 底部抽屉”不符。

**整改方向**

- 1200–1440：Inspector 可折叠为右侧抽屉，画布优先；
- <1200：工具轨变顶部横向，Inspector 用底部抽屉/侧滑，不再排到结果之后；
- 顶栏在窄屏只保留标题 + 状态摘要，详细状态进“状态”弹层。

#### F-12 源图面板在载入后仍占据 118px 投放区，标题文案不更新

**实测**

- 载入图片后，`sourceSub`（画布 header）显示 `941 × 1,672`；
- 「源图」面板的副标题仍是硬编码的 `上传后开始处理`；
- 投放区高度仍为 118px，位于工具区上方。

**影响**

- 载入后最重要的“工具参数”被源图面板推到下方；
- 文案与状态不一致，显得不精致。

**整改方向**

- 载入后源图区收成 56–64px 的紧凑卡片：缩略图、文件名、尺寸、更换/导入；
- 副标题改为“已载入 · 941×1672 · 1.6MP”；
- 空状态才展示完整投放区与三个导入入口。

#### F-13 异步任务反馈不完整

#### F-13A 主执行按钮不显眼，操作区不固定（本轮补充）

**这是本轮审查漏掉的一项，已单独补入 P0 修复清单；为便于阅读放在本节说明。**

**现状**

- 各工具的主执行按钮普遍是 `btn primary sm`，实测高度约 26px，和普通参数按钮同一视觉量级；
- 按钮放在参数流里，随 Inspector 内部滚动一起滚走。水印「应用水印」、放大「开始放大」、反推「反推标签」、导出「处理并保存」在 1280×800 下都需要先滚动才能看到；
- 同一视图出现多个 filled primary：如「调整」里同时有「应用裁剪」「应用缩放」「应用调色」；用户无法判断下一步该点哪个；
- 主次颠倒：
  - 扩图的第一步「规划扩图」是 ghost，第二步「去局部重绘」才是 primary；
  - 放大「开始放大」是左对齐的小按钮，旁边「图像对比」是 disabled 的 ghost，视觉重心落在引擎 chips 上；
  - 水印「应用水印」和「服务端预览」并排，两者都是 sm；
  - 「送入图生图」是大号 ghost block，视觉体量接近主按钮，进一步稀释层级。
- 没有固定操作区：`.tools-inspector` 是单一滚动容器，参数越长，执行按钮越靠下；
- 没有执行结果的下一动作提示，用户点完「应用裁剪」后仍停在原地，不知道可以导出。

**证据**

- [audit-04-upscale-open.png](../.screenshots/audit-04-upscale-open.png)：主操作「开始放大」为小号左对齐按钮；
- [audit-03-watermark-open.png](../.screenshots/audit-03-watermark-open.png)：主操作在长参数列表末尾；
- [audit-05-export-open.png](../.screenshots/audit-05-export-open.png)：`处理并保存` 被格式、目标体积、估算依次压在下方；
- [audit-08-1280.png](../.screenshots/audit-08-1280.png)：1280×800 下导出主按钮落到首屏之外。

**根因**

- Inspector 没有“固定操作区”这一层，所有按钮都在参数面板内部；
- 按钮尺寸体系统一用了 `sm`，没有为“当前工具主操作”定义 40–44px 的大按钮；
- 没有“一个视图只允许一个 filled primary”的约束；
- 工具切换只换参数，不同时切换底部主操作。

**影响**

- 用户不知道下一步该点哪里，产生犹豫和误点；
- 长参数工具（水印、放大、导出）每次执行都要滚动；
- 多个主按钮竞争，反而没有一个显得重要；
- 这是“商业化观感”的直接扣分项，也是本轮新增的 P0 修复项。

**整改方向**

1. Inspector 拆成「参数滚动区 + 64px 固定操作条」；操作条不随参数滚动，始终可见；
2. 一个视图只保留一个 filled primary；主按钮 40–44px 高、全宽、600 字重、圆角 10px、轻阴影；
3. 次操作改为 ghost/描边，危险操作（清空/重置）用 danger 色；
4. 当前工具的主/次操作由工具注册表声明，切工具时同步替换底部操作条；
5. 主按钮下方给一句结果说明：如“应用到当前编辑结果 · 可撤销”“保存到作品历史”；
6. 执行后主按钮进入短暂成功态，并出现下一步动作：如“已应用 · 去导出”；
7. 禁用时给出原因 tooltip（如“请先载入图片”“没有可用放大模型”），不能只降低透明度；
8. 移动端/窄屏：操作条固定在底部抽屉内，避开安全区。

**各工具操作条建议**

| 工具 | 主操作（filled） | 次操作（ghost） | 说明 |
|---|---|---|---|
| 调整 | 应用裁剪 | 重置选框 | 调色另设“应用调色”，但同屏只高亮当前分区 |
| 尺寸 | 应用缩放 | 对齐 32 | 缩放模式/滤镜进高级折叠 |
| 水印 | 应用水印 | 服务端预览 | 预览不抢占主按钮 |
| 动图 | 生成 GIF | 取消 / 拆帧 | 生成中主按钮变进度态 |
| 放大 | 开始放大 | 图像对比 | 模型缺失时禁用并给原因 |
| 扩图 | 规划扩图 → 去局部重绘 | 取消预览 | 第一步必须是 primary，规划完成后再切换 |
| 反推 | 反推标签 | 复制 | 复制在有结果后启用 |
| 导出 | 处理并保存 | 恢复默认 | 主按钮固定在操作条 |

> 注：完整版会把「调整」拆成“裁剪 / 调色”两个独立工具，从信息架构上彻底消除同屏多个主按钮；Phase 0 先通过操作条 + 当前分区高亮解决“看不见/不显眼”。

## 4. 目标体验（To-Be）

### 4.1 设计原则

沿用 `theme.css` 的令牌与 Apple 风格，不引入第二套视觉语言：

1. **内容优先**：画布最大，参数退后；当前工具参数按需出现；
2. **直接操控**：拖裁剪框、拖水印、滚轮缩放、空格平移、前后对比；
3. **渐进披露**：常用参数常驻，高级参数折叠；危险操作二次确认；
4. **即时反馈**：每个异步动作都有阶段、进度、取消、失败后的下一步；
5. **可恢复**：撤销/重做、草稿、离开确认、结果不静默丢失；
6. **一致**：同一个“当前图像”定义贯穿裁剪、水印、放大、扩图、反推、GIF。

### 4.2 目标布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ App 顶栏：页面标题 · 引擎/显存/队列状态 · 设置                        │
├──────┬───────────────────────────────────────────┬───────────────────┤
│ 工具 │ 工作区工具栏：源图名 · 941×1672 · 28%      │ Inspector 340px   │
│ 轨   │ [适应] [100%] [−] [28%] [+] [对比] [棋盘]  │                   │
│ 76px │ [撤销] [重做]                 [导出 ▾]     │ 当前工具标题       │
│      │ ┌───────────────────────────────────────┐ │ 一句话说明         │
│ 调整 │ │                                       │ │ 参数组             │
│ 尺寸 │ │              画  布                    │ │ 高级参数（折叠）   │
│ 水印 │ │      棋盘 / 前后对比 / 动图播放         │ │                   │
│ 动图 │ │                                       │ ├───────────────────┤
│ 放大 │ └───────────────────────────────────────┘ │ 64px 固定操作条    │
│ 导出 │ 状态：941×1672 · 28% · PNG · ≈2.0MB       │ [应用裁剪] [重置]  │
│ 扩图 │ ┌───────────────────────────────────────┐ │ 任务卡（可选）     │
│ 反推 │ │ 结果胶片条 112px  缩略图 × N           │ │                   │
│      │ │ [全选] [收藏] [送入编辑] [导出] [清空]  │ │                   │
│      │ └───────────────────────────────────────┘ │                   │
└──────┴───────────────────────────────────────────┴───────────────────┘
```

**尺寸建议**

- 工具轨：默认 76px（图标 22px + 11.5px 标签 + tooltip），大屏可展开为 200px 并记住状态；比 220px 更适合现有 232px App 侧边栏；
- Inspector：≥1440 用 340px；1200–1440 用 320px 且可折叠；<1200 改为抽屉；
- 工作区高度：`calc(100dvh - 顶栏高度)`，页面不滚动；
- 结果条：画布列底部固定 112px，缩略图 76–84px。

**主操作按钮层级（新增）**

| 层级 | 样式 | 使用场景 |
|---|---|---|
| Primary | accent 实心、40–44px 高、全宽、600 字重、圆角 10px、轻阴影 | 当前工具唯一的“执行”动作 |
| Secondary | 透明底 + 1px 描边、36–40px 高 | 重置、预览、对比、取消 |
| Tertiary | 纯文字/图标 | 帮助、更多、次要链接 |
| Danger | 红色描边或实心 | 清空结果、重置全部 |

- Inspector 的固定操作条放在参数滚动区之外，高 64px，始终可见；
- 同一视图只允许一个 Primary；参数里的其他动作全部降为 Secondary；
- 主按钮必须全宽，不允许左对齐小按钮；
- 禁用态保留 40% 透明度，并用 tooltip 说明原因；
- 主按钮下方一行 11.5px 说明：作用对象、是否可撤销、保存位置。

### 4.3 信息架构

工具按用户任务分组，而不是按后端接口分组：

| 分组 | 工具 | 说明 |
|---|---|---|
| 基础 | 裁剪 / 旋转翻转 / 尺寸 | 先定构图与尺寸 |
| 调整 | 调色 / 锐化 / 色温 | 轻量、即时预览 |
| 增强 | 高清放大 / 扩图 | 重任务，任务卡 |
| 内容 | 水印 / 反推 / 动图 | 生成或标注内容 |
| 输出 | 导出 | 格式、质量、目标体积、保存 |

- 工具轨只负责切换，不负责展开；
- 每个工具一个参数面板，切换不丢源图与已应用操作；
- 当前工具标题 + 一句说明，参数区不再套 `<details>`；
- 「高级」只隐藏低频参数（滤镜算法、对齐倍数、平铺角度等）。

### 4.4 状态模型（单一事实来源）

建议把现在散落在闭包里的状态拆成四层：

```
source        原始图片（dataUrl / 文件引用 / 名称 / 尺寸）
appliedOps    已应用操作（裁剪/旋转/缩放/调色/水印…），可撤销/重做
pending       当前画布上的临时状态（裁剪框、水印位置、扩图预览）
results       已落盘结果（url/thumb/尺寸/类型/时间）
```

规则：

- 只有「应用」动作能把 `pending` 转成 `appliedOps`；
- 导出只提交 `appliedOps`，不隐式提交 `pending`；
- 撤销/重做操作 `appliedOps` 快照，最多 50 步；
- 所有工具通过 `currentImage()` 取“当前结果”，不再各自读 `state.source.dataUrl`；
- 结果与草稿持久化，刷新可恢复。

### 4.5 关键流程

**裁剪 → 导出**

1. 选比例，画布上拖框；右侧显示精确输出尺寸；
2. 点「应用裁剪」：操作史 +1，画布切换为新图，选框重置为整图，比例回到“自由”；
3. 点常驻「导出」：选格式/质量/目标体积，右侧或弹层显示预计体积；
4. 保存后结果条高亮新卡，toast 提供“查看 / 送入编辑”。

**水印**

1. 进入水印工具直接看到参数；
2. 文字/图片切换；画布上拖动，九宫格/中线吸附；
3. 服务端预览与最终落盘一致；应用后进入结果条；
4. 支持“应用到当前结果 / 批量结果”。

**高清放大**

1. 默认输入 = 当前编辑结果，可切换为原图；
2. 选引擎与倍率，提交后出现任务卡（阶段/进度/取消）；
3. 离开工具组或切页，任务卡与进度仍在；
4. 完成后可 1:1 对比、继续编辑、送入图像编辑。

**扩图**

1. 规划前先确认输入图与尺寸一致；
2. 全景比例自动算方向与幅度；
3. 规划后画布显示新画布与新增区域；
4. 修改方向/幅度/比例时自动让旧规划失效，提示“参数已变，请重新规划”。

**GIF**

1. 图片序列支持拖拽排序、删帧、每帧时长；
2. 视频支持双滑块截取、fps、宽度；
3. 生成任务卡可见、可取消；
4. 结果可直接拆帧继续编辑，不需要先“继续编辑”设为源图。

### 10.0 复查方法

### 10.1 新发现的 10 个基础问题

| ID | 问题 | 实测量化 | 优先级 |

#### J-01 详细说明：窄屏工具轨不常驻

- 900×800 静态实测：顶栏 120.3px，`.tools-rail` 位于 156.3–202.3px，画布 212–728px，结果条 738–941px，Inspector 从 950.7px 才开始，页面总高 2058px；
- 工具轨在 scrollY=0 时可见，但 `position: static`，页面一滚动就离开视口；滚到 Inspector 改参数时，工具轨已被 sticky 顶栏（z-index 40）盖住，无法切工具；
- 截图 `audit2-02-900.png` 采集于滚动后的状态，所以看不到工具轨；
- 原因：≤1180 断点把布局改成单列 `rail → main → film → inspector`，工具轨取消 sticky，Inspector 被排到结果条之后；
- 修法：窄屏保留一个固定在顶栏下方的横向工具条，或把 Inspector 改成右侧抽屉；同时把结果条固定在底部，避免页面被撑到 2058px。

#### J-03 详细说明：所有工具面板都溢出

1600×950、已载入图片、展开当前折叠区后的实测：

| 工具 | 面板内容高 | Inspector 可视高 | 溢出 |
|---|---:|---:|---:|
| 调整（裁剪/宫格） | 1080 | 926 | 154 |
| 尺寸 | 1094 | 926 | 168 |
| 水印 | 1312 | 926 | 386 |
| 动图 | 1041 | 926 | 115 |
| 放大 | 933 | 926 | 7 |
| 导出 | 930 | 926 | 4 |
| 扩图 | 953 | 926 | 27 |
| 反推 | 1089 | 926 | 163 |

结论：这不是“某个工具参数太多”，而是**Inspector 的容量分配错了**。源图区占 300px、帮助区占 150px、主操作又在参数流末尾，三者叠加导致每个工具都溢出。修法优先级：源图收成 56–64px 紧凑卡 → 帮助改弹层 → 主操作固定 64px footer → 高级参数折叠。

#### J-07 详细说明：可访问性基础缺失

- 工具轨 8 个按钮没有 `role="tab"`、`aria-selected`、`aria-current`、`aria-controls`；
- 键盘无法用方向键在工具间切换，也没有 `Home/End`；
- 水印/GIF 的隐藏 file input 没有 `aria-label`，反推结果 textarea 只有 placeholder，没有可访问名称；
- Inspector 内只有 1 个 `title`，图标按钮和“?”帮助缺失；
- 空状态和异步结果没有 `aria-live` 播报。

修法：工具轨改为 `role="tablist"` + `role="tab"` + `aria-selected` + `aria-controls`；方向键/Home/End 切换；所有输入补 label；异步结果用 `aria-live="polite"`；焦点环统一用 `--accent-ring`。

### 10.2 用户任务旅程中的断点

| 阶段 | 用户目标 | 当前阻碍 | 应有体验 |
|---|---|---|---|
| 导入 | 快速拿到一张图开始处理 | 画布和右侧各有一个投放区；没有“最近使用”；不支持示例图 | 一个统一导入菜单：本地/素材/最近/剪贴板/示例 |
| 构图 | 裁到目标比例、摆正 | 无 X/Y/W/H 数值输入；无自定义比例；无拉直；比例输出不精确；应用后二次裁切 | 数值 + 拖拽双通道；精确输出；应用后选框归位 |
| 调色 | 快速得到想要的颜色 | 无自动增强、无曲线/高光/阴影/色调分离；色温只有一个滑杆；锐化只能落盘后看；无前后对比 | 常用滑杆 + 高级折叠 + 直方图 + 前后对比 |

| 标注 | 加水印、反推 | 主按钮小且靠下；水印无实时画布预览；反推只给一段文本 | 画布直接拖水印；标签 chips 可勾选；批量 |
| 输出 | 保存成目标格式/体积 | 保存入口藏在导出组；WebP 质量被隐藏；估算不准；无导出预设 | 常驻导出；格式预设；真实体积；保存后高亮 |
| 复用 | 继续编辑/送编辑/收藏 | 结果只在会话内；刷新即丢；无版本/分组 | 草稿 + 结果持久化 + 版本 + 一键复用 |
