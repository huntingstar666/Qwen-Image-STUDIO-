# 分段编辑器：合并 / 拆分 / 一句多画面

> 状态：已实施（后端合并/拆分 + 前端分段方式/试听拆分 + 主项目内嵌）· 2026-11-09
> 范围：`video_studio/` 内实现；主项目只新增「视频工作台」入口页（iframe 内嵌 8730）
> 目标：让时间线上的「字幕」和「画面」关系一眼看懂，并支持两种真实需求：
> 1. 两句（或多句）台词合并到同一个画面；
> 2. 一句台词拆成两个或多个画面（同一句字幕，多张图）。
>
> **兼容原则**：默认流程完全不变。自动分段、批量生图、导出照旧可用；
> 合并、拆分、试听选点都是用户主动触发的新增能力，不改默认行为。

---

## 1. 现状与问题

### 1.1 界面层（结合截图）

- 工具栏把「动作」和「算法参数」挤在同一行：`自动分段 | 合并间隔 350 ms | 单段上限 8000 ms`。
  用户不知道这两个数字影响什么，也不知道改完要不要重新点分段。
- 时间线有四条轨道，但没有轨道名：波形、画面、字幕、BGM 只能靠颜色猜。
- 镜头块和字幕条视觉层级太接近；块内又被「过渡 / 运镜」角标占了右上角，信息拥挤。
- 段与段之间只有 8px 的隐形拖拽热区，没有「合并」「拆分」入口；用户不知道边界可以拖。
- 看不出「这一段包含几句台词」，也看不出「这句台词被几个画面共享」。

### 1.2 数据层

当前实现（`core/segments.py`）：

- 只按字幕 cue 边界分段，一个 shot 覆盖 1..N 条 cue；
- `retime()` 只改边界，**不改 `shot.text`**；
- 没有合并 / 拆分接口。

因此：

- 拖边界把两句话圈进一段后，`shot.text` 仍是原来那句，台词与画面范围不一致；
- 一句台词无法拆成多段：边界只能落在 cue 边界，落在句子中间会被帧对齐逻辑拉回；
- 没有字段能表达「这 3 个画面属于同一句台词」。

### 1.3 产品层结论

把镜头段继续当成「字幕分组的产物」是走不通的。需要明确成三层：

| 层 | 作用 | 是否随合并/拆分变化 |
|---|---|---|
| 字幕 cue | 声音的文字，烧录字幕的唯一来源 | **不变** |
| 镜头段 shot | 画面单位，时间铺满全片，每段一张图 | 变 |
| 图片版本 | 每段的历史图 | 跟随段落合并/拆分迁移 |

---

## 2. 目标心智模型

1. **字幕是字幕，画面是画面**：一句字幕可以配 1 个、2 个或多个画面；一个画面也可以覆盖多句字幕。
2. **合并/拆分只改 shots，绝不动 cues**：
   - 字幕时间轴不变，音画同步不变；
   - 导出烧录仍按 cues，所以「一句词 3 个画面」不会出现 3 条重复字幕。
3. **时间铺满**：所有镜头段首尾相接，覆盖 0 ~ 音频总长；合并/拆分后总时长精确不变（±1 帧）。
4. **每个画面独立可控**：独立图片、独立版本、独立提示词、独立运镜。
5. **默认自动、允许手动**：段落台词默认由覆盖到的字幕自动推导；用户手改后转为手动，不再被自动覆盖。

## 3. 界面改造

### 3.1 工具栏：从「参数堆」变成「分段方式」

现状：

```
[自动分段]  合并间隔 [350] ms   单段上限 [8000] ms        3 段 · 00:12.00   [缩放]
```

改为：

```
[重新分段]  [按句分段 · 合并 0.35s · 上限 8s ▾]          4 段 · 4 段就绪   [缩放]
```

- 两个数字收进「分段方式」浮层，默认不再占用工具栏；
- 浮层内容：
  - 预设：`按句（推荐） / 按停顿（更碎） / 长镜头（更整） / 自定义`
  - 两个可解释的输入：
    - 「相邻两句间隔小于 __ 秒就合到一个画面」（合并间隔）
    - 「单个画面最长 __ 秒，超过自动切成两个画面」（单段上限）
  - 实时预览：`预计 12 段`，时间线上用虚线显示幽灵切点；
  - 底部：`[取消] [应用分段]`
- 按钮文案随状态变化：没有段时「自动分段」，已有段时「重新分段」。
- 重新分段前若有手动调整或已生成图片，明确列出后果：
  > 将覆盖 3 个手动调整的镜头段和 6 张已生成图片。`[取消] [仍然重新分段]`

### 3.2 时间线：加轨名、加段信息、加合并/拆分入口

#### 轨道名

新增左侧固定栏（不随横向滚动）：

```
┌──────┬──────────────────────────────────────────────┐
│ 时间  │ 00:00      00:05      00:10      00:15       │
│ 音频  │ ~~~~~~~~~~~~ 波形 ~~~~~~~~~~~~~~~~~~~~~~~~~~ │
│ 画面  │ [s1 小林，把灯打开] [s2 这里怎么这么冷] ... │
│ 字幕  │ [小林，把灯打开] [这里怎么这么冷] ...       │
│ 音乐  │ [BGM · -20 dB · 循环 · 闪避]                │
└──────┴──────────────────────────────────────────────┘
```

实现要点：
- 左侧 56px 固定 gutter，高度与 `--wave-h / --shots-h / --subs-h / --bgm-h` 对齐；
- `.tl-scroll` 只允许横向滚动，禁止纵向滚动；面板最小高度从 212px 提到 260px，保证四轨完整；
- 这样不需要改时间换算，也不会遮住 0 秒处的第一段。

#### 镜头块信息

- 左上：段号 `s1` + 状态点（就绪/待生成/失败）；
- 右上：运镜/转场角标保留，但缩小并放到第二行；
- 底部：台词单行省略；
- 新增角标：
  - `含 2 句`：本段覆盖多条字幕；
  - `同句 2/3`：本段是同一句台词拆出的第 2 个画面；
  - `待处理`：合并/拆分/改边界后，提示词或图片需要复核（琥珀色小点）。
- 状态颜色只用于边线/小圆点，不整块染色，避免花。

#### 选中段落操作条

在时间线工具栏下方增加一条 34px 的上下文操作条（仅当选中段落时出现）：

```
s2 · 00:06.10 – 00:12.73 · 6.6s · 含 2 句      [在播放头拆分] [与上段合并] [与下段合并]
```

- 「在播放头拆分」：播放头不在本段内时禁用，并有 tooltip；
- 「与上段/下段合并」：第一段/最后一段分别禁用；
- 所有操作都走 `pushUndo()`，可撤销。

#### 试听选点（拆分的前置动作）

拆分点不靠猜，用户用现有播放能力找切点：

1. 在段内点击 / 方向键把播放头移到想要换画面的位置（`←/→` ±0.1s，`Shift` ±1s）；
2. 空格播放、双击镜头块循环试听这一段，确认“这句话说完/停顿时”换图；
3. 点「在播放头拆分」，弹窗里再给一次 ±2s 的循环试听，可继续微调切点；
4. 确认后两段共享同一句字幕，画面在切点处切换。

- 切点默认吸附到字幕边界（120ms 内），可在拆分弹窗里关闭；
- 不做“按字符拆台词”：台词跟着音频走，图片只负责在句内完成切换。

#### 直接拖拽与合并热区

- 保留现有拖边界，但把 8px 热区做成可见的细长手柄；
- 两段之间的间隙在 hover 时浮出一个小胶囊 `合并`，点击即可合并（比先选中再点按钮更直接）；
- 拆分也可以双击段内播放头位置？**不做**，避免和「双击只播这一段」冲突。

### 3.3 分镜表：多选 + 合并

- 每行左侧加复选框（默认隐藏，hover 或已有选中时显示）；
- 选中 ≥2 个**连续**行后，顶部工具栏出现 `合并所选（2）`；
- 行右侧「更多」菜单：
  - 与上一段合并
  - 与下一段合并
  - 在播放头拆分
  - 均分为 2 / 3 / 4 个画面
- 合并后选中合并结果；拆分后选中第一段。

### 3.4 检查器

段落头部增加一行元信息：

```
s2  00:06.10 – 00:12.73   含 2 句   台词：自动
```

- `台词：自动 / 手动` 可点击；手动时出现 `恢复自动`；
- 增加两个动作：
  - `拆分本段…`
  - `合并到上一段 / 下一段`
- 待处理状态与动作统一显示在检查器顶部的「处理清单」里（见 3.6）。

### 3.5 空镜（可选扩展）

「给一句词前后加一个环境画面」可以不做成独立功能：在段首/段尾拆分出一个短段，把台词清空，即为「空镜」。
- 空镜的 `text` 为空，检查器显示「无台词」，提示词由用户手写或 LLM 只根据上下文生成；
- 字幕轨不变，空镜期间没有字幕，正好用于呼吸/转场。

### 3.6 变更后的待处理提醒

任何会让旧提示词/旧图片失真的结构变化，都自动给受影响段落打 `review` 标记。
不阻塞操作，但始终可见，避免用户忘了补提示词或换图。

- 时间线镜头块：琥珀色小点 + `待处理`；
- 分镜表：行内琥珀色胶囊；筛选器新增 `待处理`；
- 检查器顶部清单：
  - `提示词需复核` → `[重新生成本段] [标记已处理]`
  - `图片需确认` → `[重新生成] [从版本/历史选图] [标记已处理]`
- 时间线工具栏显示 `待处理 3` 计数，点击切到分镜表并筛选；
- 自动清除：
  - 提示词重新生成成功 → 清除 prompt 标记；
  - 生图 / 上传 / 切换版本 / 从历史取图 → 清除 image 标记；
  - 两个都清除后，整条 `review` 自动移除；
- 不强制：用户可以继续导出，提醒只作为质量提示；
- 拆分/合并确认后立即 toast：「已拆分，2 个画面待确认」，并提供「去处理」。

## 4. 核心算法

### 4.1 合并（两句词 → 一个画面）

接口输入：连续且有序的 `shotIds = [s2, s3, ...]`。

步骤：

1. 校验：
   - 数量 ≥ 2；
   - id 都存在、在 timeline 中连续、时间上首尾相接；
   - 合并后总长 ≥ 1 帧；不超过 30s（可配置，防一次合并太多）；
2. 新范围：`start = first.startMs`，`end = last.endMs`（后续由 `normalize_timeline` 重新推导）；
3. 新 id：沿用第一段的 id，删除其余段；
4. 台词：
   - 若所有被合并段 `textMode == "auto"` → 结果仍为 `auto`，由覆盖的 cues 重新推导；
   - 否则 → `manual`，把各段台词去重后用换行拼接，上限 2000 字；
5. 画面描述 / 提示词：
   - 取第一个非空 `description`；
   - 不做静默 LLM 调用；
   - 标记 `review.prompt = true`，用户可在检查器一键重生成；
6. 图片与版本：
   - 当前图：保留第一段当前图；若第一段没有图，取后续第一个有图的；
   - 历史：把所有被合并段的 `imageHistory` 去重后按 `at` 合并；
   - 只为「当前图」保留在 `imageHistory` 里；超过 8 条的旧文件**不删除**，只从历史里移除，避免合并导致素材丢失；
   - 状态：有当前图 → `ready`，否则 `pending`；
7. 运镜/转场：保留第一段的 `motion`；`transition` 也保留第一段（进入合并段的转场）；
8. `usedEntities` 取并集；
9. 清理 `beat`（合并后不再是「同句第几画面」）；
10. 变更标记：合并结果 `review.prompt = true, review.image = true`（一张图现在要覆盖更多台词）；
11. `normalize_timeline()` 重排 index 与首尾边界。

### 4.2 在播放头拆分（试听选点）

输入：`shotId` + `atMs`（播放头位置，由用户在试听中选定）。

1. 校验：`atMs` 在段内，距两端至少 1 帧；
2. 切点吸附（可关闭）：距最近 cue 边界 ≤ 120ms → 吸附到 cue 边界；此时两个结果都是 `auto` 台词；
3. 切在一句话中间时：两段都保留完整这句台词（`textMode = manual`）。
   **不做按字符拆分**；字幕 cues 完全不动，所以这句话只有一条字幕，图片在切点处切换；
4. 左段沿用原 id，右段生成新 id；
5. 左段保留当前图和全部版本；右段从空图、空历史开始（避免同一张图重复占两段）；
6. 描述：
   - 左段保留原描述；
   - 右段复制原描述，提示「同句的另一个画面，建议微调描述或重新生成」；
7. 运镜：右段默认 `none` 或与左段相反（push ↔ pull），避免两个画面运动完全一样；
8. 转场：右段 `cut`；
9. 若原段有 `beat`，左右段继承并重新编号；
10. 变更标记：左段 `review.prompt = true`；右段 `review.prompt = true, review.image = true`；
11. 拆分弹窗在确认前提供 ±2s 循环试听，可继续微调切点；试听窗口长度（2/3/5s）记在本地偏好。

### 4.3 均分为 N 个画面

输入：`shotId` + `parts`（2..6）。

- 时间：`start + round(duration * i / N)`，按帧对齐；最后一段 `end` 必须等于原 `end`；
- 每段都保留完整台词（同一句）；
- 复制描述到每段（复核状态由 review 标记统一处理）；
- 加 `beat` 元数据：

```jsonc
"beat": { "group": "s3", "index": 2, "count": 3 }
```

- 第一段沿用原 id，其余生成新 id；
- 图片：只有第一段保留原图，其余为空；
- 总时长必须与原段完全一致；
- 均分只是快速起点：生成后可以继续拖每一段的边界，把切点挪到试听满意的位置；
- 变更标记：所有结果段 `review.prompt = true`；第 2~N 段 `review.image = true`。

### 4.4 边界拖动后的台词一致性

新增 `shot.textMode`：

- `auto`（默认）：台词由覆盖到的 cues 自动推导；
- `manual`：用户手动改过，或由合并/拆分明确写入，不再自动改。

规则：

- `PATCH /shots/{id}` 带 `startMs/endMs` 时，先完成边界归一化，再对**所有 auto 段**执行 `reconcile_texts()`：
  - 收集与段落时间重叠的 cues；
  - 按「重叠时长更大」把跨界的 cue 归给其中一段，避免同一句重复进两段；
  - `text = 归属 cues 的文本换行拼接`；
  - 若段内没有 cue，保留原台词，并打 `warnings: ["本段没有覆盖字幕"]`（只影响提示词上下文，不影响字幕）；
- 手动段只更新边界，不改 text；
- 重算后只做 `assemble_prompt()`（代码拼装），不调用 LLM；
- 边界变化后按 4.7 标 review：受影响段 `prompt=true`；时长变化 >10% 或 >500ms → `image=true`。

`PATCH` body 增加可选项：`textMode`（`auto/manual`），检查器「恢复自动」用它。

### 4.5 合并/拆分后的提示词

- 任何合并/拆分都不自动调用 LLM，避免耗时与不可预期；
- 标记 `review.prompt = true`，前端给出「重新生成提示词」入口；
- `prompts.generate()` 处理 `beat` 时，在上下文行里加标记：

```
[s3 · 同句 2/3] 别担心，机器总会热起来
```

模板降级时追加：「同一句台词的第二个画面，换一个机位或细节」。

### 4.6 撤销与重新分段

- 合并/拆分属于镜头数据变更，复用现有 `/restore` 快照方案，前端操作前 `pushUndo()`；
- 「重新分段」会覆盖手动段，确认框需要列出：
  - 手动调整段数；
  - 已生成图片数；
  - 明确「合并/拆分会丢失，图片历史保留在磁盘但不再关联」。

### 4.7 变更标记（review）规则

只标记受影响的段，不整项目刷红；`review` 为空时删除字段。

| 操作 | prompt 需复核 | image 需确认 | 说明 |
|---|---|---|---|
| 合并 | 是 | 是 | 一张图现在覆盖更多台词 |
| 在播放头拆分 | 两段都是 | 右段是 | 右段缺图；两段共用整句台词 |
| 均分为 N 段 | 全部是 | 第 2~N 段是 | 第一段沿用原图 |
| 拖边界 | 受影响段是 | 时长变化 >10% 或 >500ms 时是 | 自动段同时重算台词 |
| 手动改台词 | 否 | 是 | 提示词会自动重拼，但台词变了建议换画面 |
| 重新生成提示词成功 | 清除 | — | 服务端自动清 |
| 生图 / 上传 / 换版本 / 历史取图 | — | 清除 | 服务端自动清 |
| 用户「标记已处理」 | 清除 | 清除 | 逐项清除 |

- 标记不阻塞生成与导出；
- 任务失败不自动清标记；
- 批量生图只清成功的段。

## 5. 数据模型

### 5.1 shot 新增字段

```jsonc
{
  "textMode": "auto",        // auto | manual
  "beat": null,              // { group: "s3", index: 2, count: 3 }
  "review": {                // 没有待处理时整个字段删除
    "prompt": true,
    "image": true,
    "reason": "split",       // merge | split | retime | text
    "at": "2026-11-09 14:20:03"
  }
}
```

- `new_shot()`：`textMode="auto"`、`beat=None`，不写 `review`；
- `apply_defaults()`：老项目补字段；
- `schema.SHOT_FIELDS`：允许 PATCH `textMode`；`beat` 由服务端维护，不允许前端乱写；
- `review` 由服务端维护，前端只通过「标记已处理」清除。

### 5.2 不变的字段

- `subtitle.cues` 完全不动；
- `shot.startMs/endMs` 仍由 `normalize_timeline()` 维护；
- `shot.image/imageHistory` 规则不变，只多一步合并迁移。

## 6. API 设计

| 方法 | 路径 | body | 说明 |
|---|---|---|---|
| POST | `/api/projects/{id}/shots/merge` | `{shotIds:[...]}` | 合并连续多段，返回完整项目视图 |
| POST | `/api/projects/{id}/shots/{shotId}/split` | `{atMs}` | 在时间点拆分 |
| POST | `/api/projects/{id}/shots/{shotId}/split` | `{parts:N}` | 均分为 N 个画面 |
| PATCH | `/api/projects/{id}/shots/{shotId}` | 新增 `textMode` | 恢复自动/手动 |
| POST | `/api/projects/{id}/shots/{shotId}/review/clear` | `{fields:["prompt","image"]}` | 用户标记已处理 |

统一规则：

- 同步执行（毫秒级），不进任务中心；
- 使用项目锁 `_lock(project_id)`，返回 `_view(project)`；
- 失败返回 `StudioError`：
  - `not_found`：段落不存在；
  - `bad_payload`：非连续、parts 越界、拆分点太靠边；
  - `too_many_shots`：超过 120 段；
- 合并/拆分后都调用 `normalize_timeline` 与 `summary`；
- 服务端自动清 review：
  - `prompts.generate()` 成功的段落清 `review.prompt`；
  - 单段/批量生图成功、上传图片、切换版本、历史取图清 `review.image`；
  - 清除后若 `review` 为空，删除该字段。

- [ ] 1280 / 900 宽下操作条不换行、按钮可点

## 9. 默认决策与风险

| 问题 | 默认决策 | 理由 |
|---|---|---|
| 一句词拆多画面，台词怎么处理 | 两段都保留整句，**不按字符拆** | 画面跟着音频走，字幕只烧一条 |
| 切点怎么选 | 用户试听 + 播放头微调；默认吸附字幕边界（可关） | 用户最清楚该在哪个语气/停顿换画面 |
| 拖边界是否改台词 | auto 段自动改，manual 段不改 | 保证时间范围与台词一致，又不覆盖手改 |
| 合并后提示词 | 保留第一段描述 + `review.prompt`，不自动调 LLM | 避免隐式耗时与风格漂移 |
| 合并后的图片 | 当前图 + 历史迁移；超 8 版只移出历史不删文件 | 合并不能造成素材丢失 |
| 一句多画面怎么让 LLM 写出不同描述 | `beat` 标记进入上下文 | 不新增用户操作，模型自然区分节拍 |
| 变更后的提醒 | 自动标 `review`，不阻塞；生成/换图后自动清 | 避免遗漏补提示词或换图 |
| 重新分段与手动修改 | 明确警告，不做「保留手动段」重排 | 首版优先可预期；保留手动段可后续再做 |

**风险**

- 一句台词被拖边界切成两段时，自动台词会把整句给重叠更多的那一段；另一段可能没有台词，需要 `warning` 提示；
- 合并后的描述可能不再准确，需要 `review.prompt` 提示，避免用户直接批量生图；
- 超长合并（>30s）会生成很长 prompt，首版限制合并总时长；
- 前端多选合并必须校验连续，否则会出现时间空洞；
- 待处理标记过多会造成噪音：只标受影响段，支持逐项 / 一键标记已处理，且不阻塞导出。

## 10. 不做的事

- 不做独立的「音频轨逐段配音」；
- 不做镜头段自由拖拽成不连续时间（会破坏字幕与音画同步）；
- 不做自动语义分镜（LLM 猜哪里该切画面）——首版只做用户可控的合并/拆分。
