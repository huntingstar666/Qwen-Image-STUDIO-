# 方案分支：工作台「主图」模型重构（主图 = 仅底图）

> 状态：**设计分支，仅文档，本轮未改任何代码**。
> 起因：2026-11-10 用户反馈「做了一轮 AI 修改后回到原始主图，其他图层全丢了」。
> 结论：现实现把「换主图」做成了「重建文档」，与小节 1 的业务模型冲突，属于设计缺陷，不是操作问题。
> 决策来源：与用户确认的三条拍板（见 §0.1），后续施工须以此为准。

---

## 0. 已拍板的语义

### 0.1 三条决策

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | “主图”是什么 | **主图 = 仅底图**（含裁剪 / 旋转 / 调色 / 污点修复），图层永远在上层实时合成 |
| 2 | 切换主图时图层怎么办 | **永远保留，坐标不动**（含回到原始主图、扩图、放大后的尺寸变化） |
| 3 | 快门快照记录什么 | **只记录主图**；卡片缩略图可显示合成观感，但切到该槽时不动图层栈 |
| 4 | 调整层语义 | 保持「作用于其下方所有内容（含底图）」；它没有独立几何，覆盖范围跟随主图尺寸 |
| 5 | 旋转 / 翻转 / 左·上扩图 / 放大 | “保留图层”不等于“坐标绝对不动”：原点或尺度变化时**按几何关系自动补偿**（旋转角、平移量、缩放），否则会错位 |

### 0.2 由此确定的业务流

```
打开/生成一张图 ──► 成为主图（底图槽）
        │
        ├─ 拖入素材 ──► 变成图层（产品图 / 文字 / 贴纸 / 形状）
        │
        ├─ AI 修改主图（可带蒙版限定区域）
        │        └─► 结果成为「新主图」，自动入底部快照槽
        │
        ├─ 图层继续叠在新主图上，位置 / 显隐 / 成组 / 顺序全部不变
        │
        ├─ 随时点「原始主图」快照 ──► 只换底图，图层仍在
        │
        └─ 随时点快门 ──► 记录当前主图状态（不动图层）
```

一句话：**同一项目内，主图只是“底图槽”里的那张图；图层是项目级资产，不随主图切换而消失。**

## 1. 现状盘点（代码锚点）

### 1.1 数据模型

`StudioDoc`（`web/src/components/studio/studioDoc.js`）：

| 字段 | 含义 |
| --- | --- |
| `image` / `sourceBlob` | 底图位图 |
| `transform` | 旋转 / 翻转 / 裁剪 |
| `adjust` | 调色 |
| `repair` | 污点修复层 |
| `mask` | 蒙版（AI 送图用） |
| `layers` / `groups` | 叠加图层与组 |
| `_history` | 撤销栈（`snapshot()` 里 `layers.map(layer => layer.clone())`，见 `studioDoc.js:153-166`） |

### 1.2 渲染管线（问题根源）

| 方法 | 位置 | 输出 |
| --- | --- | --- |
| `renderClean()` | `studioDoc.js:903` | 裁剪后的底图 + 调色 + LUT（无修复、无图层） |
| `renderUnderlay()` | `studioDoc.js:964` | 上面的结果 + 修复层 —— **这才是“仅底图”** |
| `renderBase()` | `studioDoc.js:983` | `renderUnderlay()` + `composite(layers)` —— **代码里的“主图”其实是合成图** |
| `exportCanvas()` / `bake()` / `bakeBlob()` | `studioDoc.js:1173 / 1188 / 1193` | 全部走 `renderBase()`，即含图层 |
| 画布绘制 | `studio.js:3541-3573` | 有图层且无调整层时走 `renderUnderlay()` + `drawLayers()`；否则退回 `renderBase()`（整张合成） |

所以“主图”有两个含义，代码与 UI 各说各话：
- UI/用户认为：主图 = 底图；
- 代码/导出/AI 认为：主图 = 合成图。

### 1.3 版本链与切换

| 行为 | 位置 | 现状 |
| --- | --- | --- |
| 版本记录 | `studio.js:6430 recordVersion` | 版本 = 一张扁平 PNG + 名称/时间，**不含图层/蒙版/调整** |
| 版本种类 | `original` / `manual`（快门、合并主图）/ `edit`（AI 结果自动入槽）/ `upscale` | 除 `original` 外都是从 `renderBase()` 烘焙出来的合成图 |
| 快门 | `studio.js:6675-6693` | `current.bakeBlob('image/png')` → **把图层烘焙进快照** |
| 切换版本 | `studio.js:6476-6551 switchVersion` | `new StudioDoc(image)` + `setDoc()`：**整个文档被替换**，图层/蒙版/选区/撤销栈全部归零 |
| 文档替换 | `studio.js:7847 setDoc` | 换文档时清 `layerBlobs` 缓存 |
| AI 结果“载入为新底图” | `studio.js:2448 adoptResult` | 同样是 `new StudioDoc`，图层清空 |
| AI 送图 | `studio.js:2425 getSource` | `main: doc.bake('image/png')` → **发给 AI 的是含图层的合成图** |

### 1.4 为什么旧实现“看起来合理”

因为 `bake()` 已经把图层烘焙进画面：
- 快门存的是成品图；
- AI 看到的是成品图，返回的也是含图层像素的图。

把这种图设成新主图后，如果图层还留着并显示，就会出现**图层两份**（半透明边缘发黑、阴影加深、描边变粗）。旧代码用“换文档 = 清空图层”回避了重复，代价就是现在的数据丢失。

## 3. 目标实现设计（伪代码级，未落地）

### 3.1 切换主图（D5）

```js
async function switchVersion(versionId) {
  const version = versions.find(v => v.id === versionId);
  const blob = await loadVersionBlob(version);
  const image = await loadImage(URL.createObjectURL(blob));

  // 只换底图：图层、组、图层蒙版、选中态原样保留
  doc.replaceMainImage(image, blob);   // 内部：重置 transform/adjust/mask/repair/选区/撤销栈
  currentVersionId = version.id;
  scheduleSave();                      // 保存“主图 + 图层”两条独立记录
}
```

要点：
- **不 new StudioDoc**；
- 撤销栈就地清空（“换主图”是一步原子操作，不可回退到旧主图 + 新图层混搭状态）；
- 尺寸变化时**不缩放图层**（决策 2），只更新 `doc.size` 与画布视口，必要时提示“主图尺寸已变化，图层保持原坐标”。

### 3.2 AI 送图（D3）

```js
getSource() {
  return {
    main: includeLayers ? doc.bake('image/png') : doc.bakeMain('image/png'),
    containsLayers: includeLayers,
    mask, maskSize, coverage, hasMask,
  };
}
```

- `bakeMain()` 新增：`renderMain()` → dataURL；
- 勾选「包含图层」时结果含图层像素，回流时提示“结果已包含 N 个图层，可一键隐藏重复图层”。

### 3.3 结果回流（D4）

三条入口统一：

| 入口 | 行为 |
| --- | --- |
| 「设为新主图」（原“载入为新底图”） | 只替换底图 + 入快照槽；图层保留 |
| 「作为新图层」 | 不变（文档不动） |
| 自动入槽（AI 完成后） | 只加卡片，不改主图 |

### 3.4 快门（D6）

```js
const blob = await current.bakeMainBlob('image/png');   // 仅底图
recordVersion('manual', blob, { meta: { containsLayers: false, layers: layerCount } });
```

卡片缩略图仍可用合成图渲染（仅展示用），但**槽里存的是主图**。

### 3.5 旧数据兼容（D7 / D9）

- 旧版本卡 `meta.containsLayers` 缺失 → 视为 `true`；
- 旧工程 session 的 `layers` 原样读取（本次事故的工程已被覆盖，无法恢复，属于已知损失）；
- 迁移不做批量重写，按“首次访问时补标记”处理。

## 4. 风险与开放问题（已收敛）

1. ~~调整层语义~~ → 已确认：作用于其下方所有内容（含底图），覆盖范围跟随主图尺寸；实现上调整层没有像素、只改写已合成画布，保持现有 `paintLayer` 顺序即可。
2. **剪贴蒙版**（`clipped`）：依赖下方图层像素，保持现有 `drawLayers` 顺序即可，但需回归测试。
3. **蒙版坐标系**：蒙版跟随主图尺寸；换尺寸后旧蒙版作废（`replaceMainImage` 重建空蒙版），不缩放复用，避免歧义。
4. ~~扩图方向~~ → 已确认：向右/向下扩天然不动；向左/向上扩按扩展量 (dx, dy) 平移图层；放大按倍数缩放图层位置与尺寸。扩图面板本身有四向百分比，补偿量可直接取得。
5. **导出与“合并主图”**：仍走 `renderBase()`（合成），不受本分支影响。
6. **性能**：画布展示保持现有双路径（有调整层时退回 `renderBase()`；调整层依赖“已画好的整张画布”，逐帧对视图画布做像素改写代价高）。这是展示层的实现细节，不影响“主图 = 仅底图”的语义。
7. **撤销跨“换主图”**：换主图会清空撤销栈（原子操作）；如需可撤销，需要把主图纳入 `snapshot()`，暂不做。
8. **旋转 / 翻转仍会清空图层**（`studioDoc.js:258-300` 的 `this.layers = []`）：属于 D8 范围，尚未修改，是下一阶段必须处理的同类数据丢失点。

## 12. 对象级变换与多选（阶段设计，2026-11-10）

### 12.1 问题

当前「旋转 / 翻转」固定作用于主图，图层只是被动做几何补偿；图层自身只有深藏在属性面板里的 `rotation`，没有镜像入口；多选虽有底层数据结构（`selectedLayerIds`）但 UI 未开放。用户的心智是：

> 画布 = 最底层的主图对象 + 一层层图层对象；每一层都能单独选中、单独操作，也能组合操作。

### 12.2 已拍板（2026-11-10）

| 决策 | 结论 |
| --- | --- |
| 变换按钮作用于谁 | **跟随当前选中对象**：主图 → 画布随旋转变尺寸；单图层 → 只改该层；多选 → 绕选择集中心整体变换 |
| 多选方式 | **Ctrl + 点击**（画布 / 图层面板），兼容 Shift |
| 文字层镜像 | **按 PS 一致镜像字形**（给 `TextLayer` 补镜像绘制） |

### 12.3 目标模型

- **选择目标**三态：`base`（主图）/ `layers`（一个或多个图层）/ `none`。
- 顶部常驻提示当前操作对象：「主图」「图层 3」「已选 4 个图层」。
- 所有对象级操作（旋转、翻转、删除、方向键微移）走同一个分发器：
  - `base` → `doc.rotateRight()` / `doc.flip()`（画布尺寸变化，符合预期）；
  - `layers` 单层 → 绕自身中心改 `rotation` / `flipH/flipV`（文字走镜像绘制）；
  - `layers` 多层 → 绕选择集外框中心，对每个成员应用同一变换（位置旋转/镜像 + 自身角度/翻转累加）。
- **组不引入独立变换矩阵**：组操作 = 批量对成员应用同一变换，撤销仍是一步快照。
- 画布视图稳定：主图旋转后保持视口中心，只重算缩放，避免“跳一下”。

### 12.4 实施阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 选择目标 + 主图可选（图层面板主图行、画布空白） | 点主图行高亮；状态提示“操作对象：主图” |
| 2 | 操作分发：旋转/翻转按目标；图层面板加水平/垂直镜像 | 选图层旋转 90° 只转该层，画布尺寸不变；文字镜像字形 |
| 3 | Ctrl 多选（画布 + 面板）+ 多选高亮 | Ctrl 点第二层加选；选中框覆盖所有选中层 |
| 4 | 组变换（外框中心轴）+ 编组/解组 | 多选旋转 90°，整体绕中心转，相对关系不变 |
| 5 | 视图稳定 + 对齐/分布（可选） | 主图旋转后视口不跳；多选可左/右/上/下对齐 |

### 12.5 风险与约定

- 多选变换要分别处理图片层（中心 + 角度/翻转）、文字层（锚点 + 镜像绘制）、形状层（端点映射）、透视层（quad 四点），复用现有 `_rotateLayersBy90` / `_flipLayerGeometry` 的数学，改为“作用于指定集合 + 指定轴心”。
- 主图被选中时，删除/方向键等操作要明确禁用或转为提示，不能误删底图。
- 每个阶段单独提交，便于逐段回退与真机验证。

### 12.6 实施进度（2026-11-10，已完成阶段 1–4 + 阶段 5 的视图稳定）

| 阶段 | 状态 | 落地位置 |

## 15. AI 框选报「框里没有这个图层的内容」整改（2026-11-10）

> 用户反馈：用 AI 主体选择「框选」时，框明明罩住了画面里的主体，却反复提示
> 「框里没有这个图层的内容，把框拖到图层上再试」，无法继续。

### 15.1 根因

1. `adoptLayerTarget()` 只在「当前没有对象」时才自动切图层。一旦自动切过一次，目标就**锁死**
   在那个图层；之后用户换一个位置重新框选，目标层和框不相交，`clampToSend` 得到 0×0，
   于是直接报错。这也是截图里「对象已切到…」和「框里没有…」交替出现的原因。
2. 自动切层的评分用「与框的交集面积」，铺满画布的大图层会压过真正被框住的小主体层。
3. 报错文案没有说明当前对象是谁，也没有给出「切回合成图」的出路。

### 15.2 改法

| 位置 | 改动 |
| --- | --- |
| `adoptLayerTarget()` | 当前目标图层**没有覆盖**提示时才重新评估（覆盖则尊重用户选择）；评分改为「交集面积 ÷ 图层自身面积」，同分时更靠上的图层优先 |
| `adoptLayerTarget()` 兜底 | 框落在画面内、但没有任何图层被框住时，自动切回「合成图」并提示，而不是继续用错误的图层目标 |
| 框选空交集提示 | 带图层名：`框里没有「xxx」的内容：把框拖到该图层上，或把对象切回合成图`；合成图时提示「框不在画面上」 |

### 15.3 实机验证

- 选中文字层 → 在画面另一侧框选：提示「对象已切到图层「a142.webp」」并正常发出分割请求，不再出现「框里没有这个图层的内容」。
- 选中普通图层 → 在主体上框选：目标被正确识别，请求正常返回（后端结果视框选内容而定）。
- 控制台无 error / exception。

## 21. 选区画笔实时反馈 + 图层单方向拉伸（2026-11-10）

### 21.1 选区画笔实时预览

- 原因：以前拖动时只在主画布末尾把 `selection.canvas` 以 32% 白色叠一层，主画布每帧还要重绘底图 / 图层 / 蒙版色纱；大图下手感明显滞后，浅色区几乎看不出笔迹。
- 改法：在画布上叠一张独立的 `selPreview` 画布（同尺寸、同 DPR、`pointer-events:none`），落笔 / 移动时把红色笔迹**增量**画到这一层；松手 `commitSelectionPaint()` 时清空并显示蚂蚁线。主画布是否重绘不再影响笔迹响应。
- 橡皮同样作用在预览层（`destination-out`），擦除时红色笔迹即时消退。

### 21.2 图层单方向拉伸（非等比缩放）

| 位置 | 改动 |
| --- | --- |
| `layers.js` | `OverlayLayer` 新增 `stretchX / stretchY`（默认 1），`width / height = 原始像素 × scale × stretch`；`clone()` 一并复制 |

## 22. 选区橡皮反馈 + 魔棒 / 选区画笔绑定图层（2026-11-10）

### 22.1 选区橡皮

- 蒙版橡皮（画笔工具组）一直走 `afterStamp()` 的脏矩形增量 tint，本身没有滞后问题。
- 选区橡皮此前和选区画笔共用主画布预览：overlay 一开始是空的，`destination-out` 看不出任何变化，等于「擦了没反馈」。
- 现在落笔时先用 `beginSelectionPreview()` 把**已有选区**铺成红色到 `selPreview`，再用 `destination-out` 擦；擦到哪里红色就退到哪里，松手后由蚂蚁线接管。
- 同时删掉主画布里的整张选区预览绘制，选区工具每帧不再重画整张 `selection.canvas`。

### 22.2 魔棒 / 选区画笔按当前图层工作

| 工具 | 行为 |
| --- | --- |
| 魔棒 | 选中位图层时按该层像素取色（`Doc.renderLayer`），选区写入 `source.layerId`；选中主图 / 未选图层时仍按合成图。点到图层透明像素会提示「此处是透明像素；要按整幅画面选择请先选中主图」 |
| 选区画笔 / 橡皮 | 选中位图层时选区绑定该层：已有选区先裁剪到图层可见像素，新笔迹也只落在该层 alpha 内（预览层同步裁剪）；选中主图时仍是整幅画面 |
| 下游 | 选区带 `source.layerId` 后，抠图 / 批量导出按该层取像素；不同来源的选区不会被魔棒硬拼 |

工具提示已同步说明「选中图层时按该层取色 / 只在该层可见像素内生效」。
