## 1. 目标

让「写得快的人」和「看得懂画面的人」都能独立完成一条片子，而不需要理解分段算法或提示词结构。

三条主线：

1. **信息透明**：每一段的台词、图片、提示词，一眼全见，不用逐个点选。
2. **单点可控**：任意一段都能单独重生图、换图、回退到上一版，不影响其他段。
3. **状态可追踪**：任务在排队/在跑/跑完了/失败原因，随时能看到，并接上主项目的队列与历史。

## 3. 产品原则

1. **一段一卡**：每个镜头段是一个可独立操作的对象，所有信息围绕它聚合。
2. **默认不隐藏**：能一屏展示的，就不塞进抽屉；只有低频的全局设置进抽屉。
3. **代价前置**：会覆盖/丢弃数据的操作，先提示后果，再执行。
4. **状态永远可见**：任何耗时操作都必须有入口能看到它在哪一步。
5. **克制**：不加与核心（图 → 片）无关的功能，例如站内 TTS、素材市场。

## 4. 功能方案

### 4.1 分镜表视图（O1 · P0）

**状态**：已完成（批次 A）。在舞台上方用 `时间线 / 分镜表` 分段控件切换，视图选择持久化到 `localStorage.videoStudio.view`；与时间线共用 `selectedId`，行内台词/提示词失焦保存，顶部支持状态筛选与关键词搜索。

**问题**：现在要看第 7 段的台词和提示词，必须先在时间线上点中它；4 段时还行，20 段时无法通读。

**方案**：在舞台上方加分段控件 `时间线 / 分镜表`，记忆上次选择（localStorage）。分镜表为纵向列表，一行一段：

```
[缩略图 128×72] s03  00:09.44–00:14.02  ●已就绪
台词：第三号机又漏油了，手是冷的。
提示词：暖白纸张质感，工业车间…（2 行后折叠，点「展开」看全文）
[重新生图] [上传图片] [版本 3] [定位到时间线]
```

要点：

- 列表行与时间线共用同一份 `selectedId`，双向高亮；
- 台词、提示词支持就地编辑（复用 `PATCH /shots/{id}`），失焦保存；
- 提示词默认折叠 2 行，`title` 可看全文；长列表用虚拟滚动阈值 200 段以上再考虑，先不做；
- 顶部过滤：`全部 / 待生成 / 失败 / 已就绪`，外加搜索框（匹配台词与提示词）；
- 移动端自动降级为单列卡片。

**验收**：20 段项目里，不点任何一段就能通读全部台词；搜索「漏油」能定位到 s03。

### 4.2 单段重生图与图片版本（O2 · P0）

**现状**：`POST /images/{shot_id}` 每次都覆盖 `images/s3.png`，改坏了只能重跑。

**方案**：

- 落盘改为版本化：`images/s3_v1.png`、`s3_v2.png`…，`shot.image` 指向当前版本；
- `shot.imageHistory: [{file, seed, at, jobId, width, height, source}]`，保留最近 8 版，超出删最旧文件；
- 检查器与分镜卡都提供「版本」按钮，弹出横向缩略图条：点选即切换当前版本，可「设为封面/删除」；
- 手动上传的图也进历史，标记 `source: "upload"`；
- 旧项目迁移：`apply_defaults` 时若 `image` 已存在且无 `imageHistory`，补一条 `v1` 记录，不移动文件。

**验收**：连续重生 3 次后能回到第 1 版；渲染读取的是 `shot.image`，换版本后重新导出画面随之变化。

### 4.3 任务中心（O3 · P0）

**问题**：批量生图时进度条只显示一条，排队中的任务、失败的任务都看不见；刷新页面后任务就"消失"了。

**方案**：

- 后端 `Task` 增加 `title`、`shotId`、`createdAt` 文本字段，并落盘 `_data/tasks.json`（保留最近 100 条，重启可查）；
- 新增 `GET /api/tasks?projectId=&limit=` 返回列表（含 queued/running/done/error/canceled）；
- 右上角加「任务」按钮，带未完成数量角标；点开是浮层（popover，非抽屉）：
  - 进行中：进度条 + 阶段文字 + 取消；
  - 最近完成：结果摘要（生成 N 段 / 失败 M 段）+「查看失败」跳到分镜表并选中失败段；
  - 失败项展示主项目返回的原始错误，可一键重试；
- 同一项目同一类型任务串行（现有单 worker 已保证），UI 上明确标注"排队中（前面还有 2 个）"。

**验收**：批量生图跑到一半刷新页面，任务仍在列表里继续更新。

### 4.4 接入主项目队列与历史（O4 · P0）

**目的**：生图的实际执行在主项目，用户需要知道「卡在谁那里」，并能复用主项目里已生成的好图。

**方案**：

- `GET /api/main/queue`：代理主项目健康信息，返回 `{pending, running, runningId, history}`，用于任务中心底部显示「主项目：运行中 1 · 排队 0」；
- `GET /api/main/history?limit=30`：代理 `/api/history`，只透出 `id / kind / status / prompt / images / created_at / params(seed,width,height)`；
- 新面板「历史图库」：
  - 按时间倒序列出主项目最近产物，缩略图网格；
  - 支持筛选「只看 video_studio 产生的」（依据 `job.meta.projectId`）；
  - 每张图可「用到某段」：选择目标镜头段 → 后端下载并写入该段图片历史；
- `POST /api/projects/{id}/shots/{shot_id}/image/from-history`，body `{jobId, imageIndex}`；
- 主项目不可达时，面板显示离线态，不影响其他功能。

**验收**：主项目跑过一次生图后，能在工作台历史图库里看到它，并一键用到 s02。

> 实现提示：主项目 `Job.to_summary()` 已包含 `images`、`params`（[jobs.py](../qwen-image2.1/server/jobs.py#L143-L155)），无需改主项目。

### 4.5 苹果风格对齐（O5 · P0）

**状态**：主体已完成（批次 A）：防主题闪烁内联脚本、顶栏玻璃层次、iOS 分段控件、内联 SVG 图标、骨架屏、焦点环、`prefers-reduced-motion` 降级、空状态。剩余「亮/暗手动切换」与数字排版细节留到批次 D。

**已有**：暖白/墨绿/暖赭色卡、16/12/8 圆角、SF Pro 字体栈、`--shadow`、toast。

**需要补齐**（按主项目 `theme.css`、`shell.css`、`studio.css` 的既有语言）：

| 项 | 具体做法 |
|---|---|
| 防主题闪烁 | `index.html` `<head>` 内联脚本，读 `localStorage.videoStudio.theme` 并预设 `data-theme`，与主项目 `qi21.workbench.settings.v1` 同思路 |
| 玻璃层次 | 顶栏 `backdrop-filter: blur(22px) saturate(1.2)`；任务浮层 `blur(34px) saturate(1.5)`；与 `shell.css` 数值一致 |
| 分段控件 | `时间线 / 分镜表` 用 iOS 风格 segmented control（滑块指示器，`--dur` + `--ease`） |
| 图标 | 内联 SVG 替换字符图标：播放/暂停/新建/关闭/设置/导出/取消；统一 20×20、`stroke-width: 1.8`、`currentColor` |
| 动效 | 视图切换 `page-in`（位移 6px + 淡入 180ms）；卡片 hover 抬升 1px；遵守 `prefers-reduced-motion` |
| 焦点 | `:focus-visible` 统一 `outline: 2px solid var(--accent-ring)`，键盘可达 |
| 空状态 | 分镜表/历史图库的空态用图标 + 一句说明 + 主按钮，不用纯文字 |
| 骨架屏 | 图片未加载完成时显示 `--panel-2` 骨架 + 轻微脉冲，避免闪白 |
| 主题切换 | 顶栏加亮/暗切换，持久化；跟随系统为默认 |
| 数字排版 | 时间码、段号统一 `--mono`，字间距 `-0.01em`，避免跳动 |

**不做**：不引入组件库、不做侧边栏导航（单页工作台不需要）、不做自定义主题色（与主项目区分度靠布局，不靠颜色）。

## 6. 数据结构变更

### 6.1 `shot` 新增字段

```jsonc
{
  "image": "images/s3_v2.png",
  "imageHistory": [
    { "file": "images/s3_v2.png", "seed": 20261109, "at": "2026-11-09 14:02:11",
      "jobId": "job-xxxx", "width": 1536, "height": 864, "source": "generate" },
    { "file": "images/s3_v1.png", "seed": 20261109, "at": "...", "source": "generate" }
  ],
  "promptHistory": [
    { "at": "2026-11-09 13:58:02", "text": "…", "source": "llm" }
  ]
}
```

- 只在内容真正变化时追加 `promptHistory`，最多 10 条；
- 版本文件超 8 个时删最旧，并从历史里移除；
- `apply_defaults` 负责补字段与旧项目迁移。

### 6.2 任务落盘

```jsonc
// _data/tasks.json
{ "tasks": [ { "id": "task-…", "kind": "images", "projectId": "vid-…",
  "title": "批量生图", "status": "done", "progress": {...},
  "result": {...}, "error": "", "createdAt": 1762... } ] }
```

- 保留 100 条；启动时加载；运行中的任务标记为「中断」而非失败。

## 7. API 契约（新增/调整）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tasks?projectId=&limit=50` | 任务列表（新增） |

## 10. 风险与回滚

| 风险 | 处置 |
|---|---|
| 图片版本化让磁盘膨胀 | 每段限 8 版 + 项目详情页显示占用；后续加「清理未使用版本」 |
| 任务落盘与内存不一致 | 以内存为准，落盘仅追加；启动时把 `running` 修正为 `interrupted` |
| 主项目不可达 | 所有代理接口返回 503 + 明确文案，前端降级为只读历史缓存 |
| 分镜表与时间线状态不同步 | 统一走 `setState({selectedId})` + 单一渲染入口，禁止各自维护选中态 |
| UI 改动破坏现有布局 | 每批提交前跑一次 1920×1080 与 1280×800 两档截图对比 |
