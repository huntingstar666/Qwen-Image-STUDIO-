> 状态：方案建议，待确认后实施 · 2026-11-09
> 范围：`video_studio/` 为主；主项目只保留「视频工作台」入口页
> 目的：先对齐“要解决什么问题、怎么解决、边界在哪”，再动代码

---

## 0. 结论摘要

| 问题 | 结论 |
|---|---|
| 播放时拖播放头，线会自己跑 | 拖拽期间进入「拖拽模式」：暂停画面跟随，松手后再 seek；正在播放则松手恢复播放 |
| 预览只有切图，没有镜头运动/转场 | 预览层改成两层图片 + 时间驱动：运镜用 scale/translate，转场用透明度/黑场，复用导出端的帧计算 |
| 切分与换图 | 在轨道上直接切（S 键 / 右键 / 播放头剪刀），选中段后就地出现「换图 / 重新生成 / 版本」工具条 |
| 背景音乐 | 目前只有后端接口，没有入口；BGM 轨道点击即可上传，轨道上直接调音量和闪避 |
| 资产锁 | 把现在的「内容锁手填实体」升级成：LLM 抽取 → 候选清单确认 → 资产卡（含参考图）→ 全片/全章节强制引用 |
| 长篇分段 | **一个项目 = 多章节（chapter）**；资产、风格、画幅、渲染设置属于项目，音频/字幕/镜头属于章节；导出按章节渲染再拼接 |
| 边界 | 建议单章 ≤30 分钟、单项目 ≤4 小时、单章镜头 ≤300、单章字幕 ≤2000 条；超过就新建章节 |

我的建议顺序：**先修 P0（播放头、预览、轨道切分/换图、BGM）→ 再做资产锁 → 最后做章节化长篇**。
资产锁和章节都会改数据模型，先把日常手感修好，再做结构升级，返工最少。

## 1. 现状盘点（为什么会出现这些问题）

### 1.1 播放头与拖拽

- [main.js](file:///<PROJECT_ROOT>/video_studio/web/src/main.js) 的 `loop()` 每帧执行
  `timeline.setPlayhead(currentMs())`，播放头完全由音频时间驱动。
- 时间线 `_startSeekDrag()` 只负责在拖动时 `seek()`，没有告诉播放循环「用户正在拖」。
- 结果：一边播放一边拖，rAF 每帧把播放头写回音频当前时间，看起来就是「线自己往后跑」。

**结论：这不是动画性能问题，是缺少拖拽状态。** 修法很确定，不需要改架构。

### 1.2 预览只切图

- `renderStage()` 只做三件事：换 `img.src`、贴字幕、切空状态。
- 导出端 [render.py](file:///<PROJECT_ROOT>/video_studio/core/render.py) 已经有：
  - `render.timeline(project)`：每段帧数、转场帧数、切点；
  - `_motion_state(kind, zoom, progress, ...)`：推/拉/横移/摇镜的缩放与偏移；
  - 转场：`cut / fade / fadeblack`。
- 预览端完全没用这些信息，所以用户看不到自己调的运镜和转场。

### 1.3 切分与换图

- 切分已有接口与弹窗（`split_shot_at` / `split_shot_parts`），入口在「选中段上下文条」和检查器里。
- 换图/重生成已有接口，入口在检查器与分镜表。
- 但时间线本身仍然是「只读展示」：不能在轨道上切、不能在轨道上换图，必须先去侧栏。
  对剪辑手感来说这是断的。

### 1.4 背景音乐

- 后端已有 `POST /api/projects/{id}/bgm`、`DELETE .../bgm`，渲染端也支持音量/循环/闪避。
- 前端只有隐藏的 `#fileBgm` 与 `pipelineAction("bgm")`，**没有任何可见入口**；
  设置抽屉里只能看到 BGM 文件名文本，不能上传。
- 结论：BGM 功能「后端通、前端断」。

### 1.5 资产与长篇

- 现在的「内容锁」= 用户手填 `{kind,name,desc}` 列表，`fill_continuity()` 只在同项目内把上一段角色带到下一段。
- 没有「自动从台词/小说抽取主要人物与场景」，没有参考图，没有跨章节继承。
- 项目只有一份 `audio/subtitle/shots`；字幕 cues 上限 2000、镜头上限 120，长篇小说无法装进一个项目。

## 2. P0：先修手感（不改数据模型）

### 2.1 播放时拖拽播放头

**交互规则**

1. 在标尺/波形/任意轨道按下拖动 → 进入 `scrubbing` 状态：
   - 立即暂停「播放头跟随音频」，只跟随鼠标；
   - 如果音频正在播放，暂停音频（避免声音和画面错位）；
2. 拖动过程中实时预览对应时间点的画面（节流到 ~30fps）；
3. 松手：
   - 最终位置 `seek()`；
   - 松手前如果是在播放，自动从新位置继续播放；
4. 底部进度条（`#seek`）拖动遵循同一套规则。

**实现要点**

- `main.js` 增加 `scrubbing` 标志；`loop()` 里 `if (!scrubbing) timeline.setPlayhead(...)`；
- `timeline.js` 的 `_startSeekDrag` / 拖动边界增加 `handlers.onScrubStart/onScrubEnd`；
- 拖边界（改段落时长）时同理：不跟音频，松手再提交 retime。

**验收**

- 播放中按住播放头拖动 3 秒，线严格跟手，不出现回弹；
- 松手后音频从松手位置继续，不断音；
- 拖边界时画面不再自己跳段。

### 2.2 预览：运镜 + 转场

**目标**：预览要能看出「推/拉/横移」和「淡入/黑场」，不是幻灯片。

**方案（推荐，分两步）**

- **P0：DOM 双层预览**
  - 舞台内放两层 `<img>`：`A` 当前段、`B` 下一段（或上一段）；
  - 用 `render.timeline(project)` 拿到当前时间落在哪一段、转场窗口是哪几帧；
  - 运镜：根据 `_motion_state()` 的结果换算成 `transform: scale(z) translate(x,y)`；
  - 转场：`fade` 用 `B` 的 opacity 从 0→1；`fadeblack` 先压黑再抬黑；
  - 由 `requestAnimationFrame` 驱动，音频 `currentTime` 作为唯一时间源；
  - 拖动预览时降级到 15–30fps，不追求逐帧精确。
- **P1：Canvas 预览（可选）**
  - 如果 DOM 双层在快速拖拽时掉帧，再用 Canvas 2D 重绘同样的状态；
  - 好处是可以顺带预览水印、字幕位置、构图裁切；
  - 与导出端共用同一份 `render.timeline` 帧数据，避免「预览和成片不一样」。

**必须遵守**

- 预览只做「可信近似」，不承诺像素级等于导出；
- 没有图片的段落显示占位（第一帧可用上一段图模糊替代，明确标注「待生成」）；
- 转场时长改动后预览立即生效，不需要重新生成。

**验收**

- 给一段设「慢推」，播放时能看到画面缓慢放大；
- 两段之间设 400ms 淡入，播放时能看到交叉淡化；
- 黑场能看到压黑再出现；
- 切换段落拖动时没有明显卡顿（1280×900 下 ≥30fps）。

### 2.3 轨道上切分 + 就地换图

**你表达的意思我理解为：**
> 不用先跑去侧栏。播放头停在想切的位置，直接在轨道上切；切完选中任意一段，就能在轨道上把这张图换掉或重新生成。

**交互设计**

1. **切分**
   - 选中段 + 播放头在该段内 → 按 `S`，或点段上浮出的剪刀按钮，或右键「在播放头拆分」；
   - 段内显示一条虚线预览切点（吸附字幕边界时高亮提示）；
   - 切完自动选中左段，右段打「待补图」标记。
2. **选中段就地工具条**
   - 选中镜头块后，块上方浮出：`换图` `重新生成` `版本 N` `清空` `拆分` `合并`；
   - 工具条不遮挡台词，鼠标移出后淡出，点击段内任意位置保持显示；
3. **右键菜单**（时间线 / 分镜表统一）
   - 在播放头拆分、与上段合并、与下段合并、换图、重新生成、复制提示词、标记已处理；
4. **拖拽换图**
   - 从桌面拖一张图到某个镜头块上 → 直接替换该段图片（复用现有上传接口）。

**实现要点**

- 时间线已有选中态和 `selectedId`，只需增加浮动工具条与右键菜单；
- 换图/重生成直接复用 `POST /shots/{id}/image`、`POST /images/{id}`；
- 拖拽上传需要给 `.shot-block` 加 `dragover/drop`；
- 所有操作继续走 `pushUndo()`。

**验收**

- 播放头在段内按 `S` 能切开，总时长不变；
- 选中段后不离开时间线就能换图/重新生成；
- 拖图到段上能替换，并出现「已替换」提示；
- 所有操作可 Ctrl+Z 撤销。

### 2.4 背景音乐（BGM）

**现状**：后端完整，前端无入口。

**设计**

- BGM 轨道（时间线第 5 轨）从「展示」变成「可操作」：
  - 空状态显示「点击上传背景音乐」，点击打开文件选择；
  - 已有 BGM 时显示文件名/时长，悬停出现「更换 / 删除 / 试听」；
  - 轨道右侧直接放 `音量 -18dB`、`循环`、`闪避` 三个小控件（改动即时 PATCH `render.bgm`）；
- 检查器新增「背景音乐」区块，与轨道控件双向同步；
- 上传后自动铺满全片（循环），并给出「原声闪避」默认开启；
- 试听走现有音频播放链路：BGM 单独一条 `<audio>`，与主音频同步播放/暂停。

**边界**

- BGM 只支持一个文件；多段音乐先用剪辑软件拼好或后续做「音乐段落」；
- BGM 改动不影响导出时长。

**验收**

- 不上传时轨道显示上传入口；
- 上传后播放能听到 BGM，音量/闪避改动立即生效；
- 删除后回到空状态，导出无 BGM。

## 3. 资产锁（Asset Lock 2.0）

### 3.1 目标

把「人物/场景一致性」从**手工填卡片**升级为：
1. LLM 从台词或小说原文里找出主要人物、主要场景、关键道具；
2. 用户确认候选清单（合并同义、删除路人）；
3. 每个资产生成固定外观描述与参考图（人物三视图、场景定场图）；
4. 全片（以及后续所有章节）生图时强制引用同一份资产描述与参考图。

### 3.2 数据模型（建议扩展现有 entities）

```jsonc
"assets": {
  "enabled": true,
  "strict": true,
  "items": [
    {
      "id": "e1",
      "kind": "character",            // character | location | prop
      "name": "小林",
      "aliases": ["小林", "他", "林工"], // 用于台词匹配与合并
      "desc": "短发，深蓝工装，右手食指有旧伤",
      "appearance": {                  // 生图锚定用
        "age": "三十多岁",
        "hair": "黑色短发",
        "outfit": "深蓝色工装，左胸有白色编号",
        "features": "右手食指缠绕胶布"
      },
      "refImages": ["assets/e1-front.png", "assets/e1-side.png"],
      "locked": true,                  // 锁住后 LLM 不得改写
      "sourceCueIds": ["c12", "c18"],  // 证据：从哪些台词抽出来的
      "firstSeenMs": 6100,
      "chapters": ["c1", "c3"]
    }
  ]
}
```

- 现有 `locks.content.entities` 迁移到 `assets.items`（`apply_defaults` 一次性迁移，保留旧的 `desc`）；
- 提示词装配顺序不变，只把「实体描述」替换成 `name + desc + appearance`；
- 生图时把 `refImages` 作为参考图传给主项目（如果主项目接口支持），不支持时退回纯文本锚定。

### 3.3 流程

```
[分析原文] → [候选资产清单] → [用户勾选/合并/改名] → [资产卡+参考图] → [锁住]
      ↑                                                              ↓
  字幕 / 小说章节                                            提示词 & 生图始终引用
```

1. **分析**
   - 入口：「流程」里的「分析资产」按钮，或首次生成提示词前提示；
   - 输入：当前项目全部字幕（分章节时按章节）；
   - LLM 只输出候选 JSON：`name / kind / aliases / evidence(台词原文) / confidence`；
   - 分块处理（每 40 条字幕一块），最后按 `aliases` 合并去重；
   - 不自动写入，必须先给用户确认。
2. **确认**
   - 候选清单：默认全选主要角色与反复出现的场景，路人/一次性道具默认不选；
   - 支持合并两个候选、改类型、补别名、手动新增；
3. **资产卡**
   - 人物：固定外观字段 + 可选三视图（可用主项目图生图批量生成）；
   - 场景：定场图 + 光线/材质关键词；
   - 道具：外观 + 首次出现镜头。
4. **锁定与继承**
   - `locked: true` 后 LLM 只能引用、不能改描述；
   - 后续章节共享同一份资产（`chapters` 记录出场章节）；
   - 生图提示词里注入 `appearance`，并尽量带参考图。

### 3.4 LLM 抽取契约（草案）

```json
{
  "assets": [
    {
      "kind": "character",
      "name": "小林",
      "aliases": ["小林", "他"],
      "evidence": ["小林，把灯打开", "他叹了口气"],
      "confidence": 0.92
    }
  ]
}
```

- 系统提示明确：只抽「反复出现、有台词或动作驱动」的对象；不要把「机器」「灯」等泛称当道具；
- 证据必须来自输入原文，找不到证据的候选直接丢弃；
- 置信度低于阈值（如 0.55）默认不勾选。

### 3.5 锚定规则

- `strict` 开启：出现未登记人名/场景时，提示词警告并阻止直接生图（可一键加入资产）；
- `fill_continuity` 升级：按 `aliases` 与「上一段角色」双路回退；
- 同一角色跨章节：`seedBase` 固定 + 资产描述固定 + 参考图固定，保证「换章不换脸」；
- 资产描述修改后，受影响镜头标记 `review.prompt`，提示重新生成提示词/图片。

### 3.6 降级

- 没配 LLM：退回「关键词 + 台词出现频次」的规则抽取（角色名按引号/称呼词，场景按地点词）；
- 参考图生成失败：只保留文本锚定，不阻塞；
- 用户不启用资产锁：完全走现有内容锁逻辑，行为不变。

## 4. 长篇与多章节（核心结构升级）

### 4.1 为什么不能只做「一条很长的轨道」

- 数据层：单项目 2000 条字幕、120 段镜头的上限会直接卡死长篇小说；
- 性能层：时间线渲染所有镜头块、波形峰值、字幕条，几小时音频会明显卡；
- 操作层：用户改第 3 章时，不想让第 1 章的图片/撤销栈参与；
- 渲染层：一次导出 2 小时视频，失败重试成本极高。

**结论：长篇必须分章。**

### 4.2 推荐模型：项目 → 章节

```jsonc
"project": {
  "canvas": {...}, "locks": {...}, "assets": {...},
  "render": {...}, "llm": {...}, "image": {...},
  "chapters": [
    {
      "id": "ch1", "title": "第一章 夜班",
      "audio": {...}, "subtitle": {...}, "shots": [...],
      "segments": {...}, "prompts": {...}, "outputs": [...]
    }
  ],
  "activeChapterId": "ch1"
}
```

- **项目级**：画幅、帧率、风格锁、资产锁、生图/LLM 参数、BGM 默认值；
- **章节级**：音频、字幕、镜头、分段参数、提示词、导出记录；
- 现有项目迁移成单章 `ch1`，接口行为保持不变（默认操作 `activeChapterId`）。

### 4.3 同一项目内如何继承

1. **资产继承**：资产挂项目级，章节只记录「本章出现了谁」；新章节生图自动带同一份资产描述与参考图；
2. **风格继承**：风格锁、seed 基线、一致性 LoRA 项目级共享；
3. **连续性**：章节内沿用 `fill_continuity`；跨章节时用「上一章最后一个镜头出现过的角色」作为初始上下文；
4. **镜头语言**：允许每章覆盖，但默认继承上一章最后一段的运镜策略；
5. **BGM**：项目级默认 BGM，章节可覆盖（例如片头/片尾不同）。

### 4.4 分章创作流程

- 「新建章节」：命名 → 上传本章音频/字幕 → 自动分段；
- **追加音频不覆盖**：新音频进新章节，避免把已做好的镜头冲掉；
- 章节切换器放在顶栏项目名右侧：`深夜车间 · 独白 / 第一章 ▾`；
- 章节列表显示：时长、段数、就绪数、待处理数；
- 「合并导出」：逐章渲染 → ffmpeg concat（无重编码）→ 输出全片；
- 单章可单独导出，导出记录按章节归档。

### 4.5 边界与上限（建议值）

| 维度 | 建议上限 | 超限处理 |
|---|---|---|
| 单章音频 | 30 分钟 / 200MB | 提示拆章 |
| 单项目总时长 | 4 小时 | 提示另建项目（或归档旧章节） |
| 单章镜头 | 300 段（从 120 提高，可配置） | 提示调大单段上限 |
| 单章字幕 | 2000 条 | 提示拆章 |
| 章节数 | 建议 ≤24 章 | 超过提示用「系列项目」 |
| 同时运行任务 | 1 个 | 复用现有单 worker |

> 这些是**产品边界**，不是技术极限；先设边界，避免用户把 10 小时音频塞进来后全链路卡死。

### 4.6 性能策略

- 波形峰值按当前缩放级别降采样，不一次画全量点；
- 时间线只渲染视口附近的镜头块（简单虚拟化：`scrollLeft` + 缓冲）；
- 章节切换只加载当前章，其他章只保留摘要；
- 导出按章独立，失败只重试该章；
- 资产参考图按需加载缩略图，原图只在生图时读取。

### 4.7 迁移策略

1. `apply_defaults` 把旧项目包成 `chapters: [ch1]`，顶层旧字段保留只读兼容一个版本；
2. 所有接口增加可选 `chapterId`，不传则用 `activeChapterId`；
3. 前端先只显示单章，等章节 UI 上线后再开放新建章节；
4. 旧项目打开无感，避免一次性大迁移导致用户数据风险。

## 5. 界面交互还能怎么优化

### 5.1 信息架构

- **一个页面只保留一条顶栏**：主项目嵌入时，去掉主项目页那层「视频工作台 · 已连接 · 新窗口打开」的重复标题，把状态并入工作台顶栏；
- 顶栏结构建议：`项目 ▾ | 章节 ▾ | 上传音频 上传字幕 | 任务 | 导出`；
- 项目下拉升级为菜单式：最近项目 + 全部项目 + 新建 + 重命名/复制/删除（危险操作二次确认）；
- 章节下拉：章节列表 + 新建章节 + 合并导出。

### 5.2 时间线

- 左侧轨名固定已有；再增加「折叠空轨」（没有 BGM 时收起 BGM 轨，需要时展开）；
- 播放头增加时间气泡，拖动时显示 `00:12.34`；
- 缩放增加「适应全片 / 选中段 / 1 秒」三个快捷档；
- 镜头块 hover 显示工具条（换图/重生成/拆分/合并），不用先选中；
- 空格播放、`S` 拆分、`Delete` 清空画面、`←/→` 微调、`Shift+←/→` 1 秒，全部可发现（快捷键面板 `?`）。

### 5.3 检查器

- 顶部固定「这一段现在缺什么」：无图 / 待复核 / 台词手动 / 无字幕覆盖；
- 资产锁开启时，显示本段引用的资产卡（头像/场景缩略），点击可跳到资产详情；
- BGM、章节信息不要塞进检查器，放到各自轨道/顶栏。

### 5.4 反馈与容错

- 所有长操作都有任务中心记录（已有），补「失败原因 + 重试」直达；
- 上传失败明确说「文件是 .txt，音频需要 mp3 / wav / …」；
- 网络/主项目离线时，禁用生图按钮而不是等失败；
- 每次结构变化（合并/拆分/重新分段）都给出「影响了哪些段」的摘要。

### 5.5 视觉

- 时间线信息层级：段号/状态点 → 画面 → 台词；运镜/转场角标降级到第二行；
- 待处理用琥珀色小点统一，不要整块染色；
- 深色模式下的图片遮罩和字幕对比度再检查一轮。

## 6. 实施顺序与验收

### P0（手感修复，不动数据模型）

1. 拖拽播放头/进度条时不跟随音频；
2. 预览支持运镜与转场（DOM 双层）；
3. 时间线内切分 + 选中段换图/重生成 + 拖图替换 + 右键菜单；
4. BGM 轨道上传/音量/闪避/删除/试听。

**验收**：播放中拖拽不回弹；能看出推拉和淡入；不离开时间线完成切分和换图；BGM 能上传并听到。

### P1（资产锁）

1. `assets` 数据模型与旧实体迁移；
2. LLM 抽取候选 + 确认界面；
3. 资产卡（描述 + 参考图）与提示词/生图锚定；
4. 资产变更后的 review 提醒。

**验收**：导入 3 章台词能抽出一致的人物/场景；锁住后生图描述不变；改资产会提示受影响镜头。

### P2（章节化长篇）

1. 项目 → 章节数据迁移与接口 `chapterId`；
2. 章节切换/新建/删除/合并导出；
3. 长音频性能：峰值降采样、时间线虚拟化、分章渲染；
4. 边界提示与超限拦截。

**验收**：一个项目装 3 章、每章 20 分钟；切换章节不丢资产；可单章导出与全片拼接；4 小时项目不卡死。

## 7. 风险与取舍

| 风险 | 处理 |
|---|---|
| 预览与导出不完全一致 | 明确「预览是近似」，共用帧计算，优先保证运镜方向/转场时机一致 |
| 资产锁 LLM 抽取不准 | 必须用户确认；低置信度默认不选；保留手动编辑 |
| 章节迁移影响旧项目 | 旧项目自动包成单章；接口保持兼容；先迁移数据再开 UI |
| 长音频内存/渲染压力 | 分章 + 单 worker + 章节级导出；设产品上限 |
| 参考图依赖主项目能力 | 主项目不支持参考图时自动退回文本锚定，不阻塞 |
