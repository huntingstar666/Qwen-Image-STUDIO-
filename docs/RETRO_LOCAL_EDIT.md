小遮罩（<2%）允许自动改用整画布执行 同一预设 吗？（任务/预设不变，只换执行策略）# 局部编辑失效复盘与整改方案

> 触发案例：2048×1365 人像，衣领处一枚小国旗徽章（约 40×30 px），遮罩覆盖 0.95%，
> 指令「去掉衣领上的小国旗」。
> 参考实现：`qwen2.1九步局部编辑API.json`、`qwen2.1元素移除API.json`、`qwen2.1扩图API.json`。
> 结论先行：**局部编辑失败的根因是"裁块后没有把整图作为第二参考图送进模型"，以及采样画布比孤海小一半；不是模型能力问题，也不该用"替用户判断任务"来绕过。** 上一版把根因写成"没传 noise_mask"是误判，已在本版更正。

| `GH_CropRestore` #21 | 扩展 3%、羽化 3% | |

### 2.4 三份工作流的共同点

1. **采样前都裁块**，裁块再按长边 768~2048 / 32 对齐缩放；
2. **采样画布固定 1024×1024（`mode=填充`）**，裁块 contain 进去，四周补色；
3. **都不传 noise_mask**，整块全量重绘；
4. 还原统一走 `GH_CropRestore`（百分比扩展/羽化 + 逐通道颜色还原）；
5. 差异只在**上下文图**与**标记方式**：
   - 局部编辑：`image_02`=整图（语义上下文）；
   - 元素移除：绿区烤进裁块（视觉标记），无上下文图；
   - 扩图：灰边 + 文本描述，无上下文图。

## 4. 根因结论

1. **首因（决定性）：方案 B 把"上下文"裁掉了。** 孤海裁块后仍把整图作为 `image_02` 送进编码器；我们只送裁块。对"去掉衣领上的小国旗"这类需要**语义定位**的小目标，模型没有全局信息，只能把裁块原样重画。
2. **次因：采样预算更小。** 孤海固定 1024²，我们 768×640；同样的裁块，模型可用像素少约一半，小目标边缘更容易被"保守保留"。
3. **第三：局部编辑预设没有删除约定**（`hint=none`、无 Remove LoRA、`fills=false`）。这不是 bug，但意味着"删除类指令"在局部编辑预设下没有任何视觉先验，只能赌提示词理解。
4. **已证伪：补 noise_mask。** 实验表明只补裁块遮罩，本用例仍保留徽章（changed 0.04%），且与绿提示叠加会在遮罩边缘留下绿色描边。孤海本来也不传，此项撤销。
5. **软边遮罩的边界问题仍在**：绿提示若用软边遮罩生成，边缘会残留绿色。孤海用硬边遮罩（Goohai LoadImage 的 alpha 0/255），这一项仍需修。

## 5. 我犯的错误

1. **替用户做条件判断**：按提示词把任务自动改成 `remove`。已撤销，代码中不再有任何"根据提示词改任务/预设"的分支。
2. **没先读参考实现就下结论**：上一版把根因写成"没传 noise_mask"，实际孤海也不传，真正的差异是 `image_02`。先读工作流再改代码。
3. **把"换预设"当方案**：让用户改用元素移除，等于承认局部编辑不可用却不修它。
4. **验收口径太弱**：只看肉眼，没有"同图 / 同遮罩 / 同种子"的对照矩阵与量化指标。

## 6. 整改措施

### P0｜让局部编辑具备孤海的语义上下文

| 编号 | 措施 | 验收标准 |
| --- | --- | --- |
| M1 | 方案 B 追加整图作为第二参考图：`ref_images = [crop, full_canvas, ...]`（整图按 1MP、32 对齐缩放，与孤海 `image_02` 对齐） | 本用例（遮罩 0.95%、指令"去掉衣领上的小国旗"）在 mask_edit 下 changed_ratio ≥ 遮罩占比；肉眼确认徽章消失 |
| M2 | 局部编辑的采样画布对齐孤海：长边目标 1024（裁块长边 <1024 时放大到 1024；>1024 时缩到 1024），contain 填充，保持 32 对齐 | 与孤海 latent 预算一致；单次耗时增幅 < 30% |
| M3 | `mask_edit` 预设的 `local.fills` 改为 `true`（与九步工作流一致） | 裁块包围盒与孤海一致；遮罩外仍 `outside_max_abs == 0` |
| M4 | 绿提示用**二值遮罩**生成（`mask > 0.5`），合成/还原仍用原始软边 | 移除用例输出无绿色描边 |

| 编号 | 措施 | 验收标准 |
| --- | --- | --- |
| M5 | 结果面板展示：任务、提示图、LoRA、scheme、裁块尺寸、上下文参考图、遮罩覆盖率、changed_ratio | 不翻日志即可判断这次做了什么 |
| M6 | 预设卡片写清能力边界（"删除小目标"用移除或整画布），但**不自动改用户选择** | 说明与实测一致 |

### P2｜回归基线

| 编号 | 措施 | 验收标准 |
| --- | --- | --- |
| M7 | 对照矩阵：3 张图 × 3 类指令（删除/替换/换色）× 4 条路线（a / b / native / remove），固定种子 | 每次改 pipeline 必须附矩阵结果 |

## 11. 我们自己的优势（整改中必须保留）

1. **零偏移承诺**：画布 32 对齐、`resolution=0`、整数裁回、遮罩外 `outside_max_abs == 0`；孤海做不到字节级。
2. **颜色只在遮罩内 + 过渡带生效**：锚区仿射 gain/offset + 过渡带 Reinhard + 可选抖动，遮罩外一次都不赋值。
3. **参数事实源清晰**：预设 / 覆盖项 / 全局默认 / 恢复默认 / 冲突校验，前端只渲染不复制常量。
4. **任务约定统一**：移除/扩图/全景的提示图、LoRA、指令自动对齐，且任务 LoRA 不会被自定义 LoRA 挤掉。
5. **工程形态**：单服务、进程内推理、不依赖 ComfyUI 服务；结果带质量字段（changed/leak/zero-shift/size_match）。
6. **可解释的裁块参数**：上下限、四向系数、百分比接缝都可在高级参数里改，且与后端校验一致。
7. **提示词工程（PE）已经具备**：`server/prompt_polish.py` + `pe_system_prompt_edit.txt`，支持带参考图/姿态、`<imageN>` 语义映射、原文↔润色对比与一键回退；孤海的 PE 是工作流里的黑盒节点，我们的是可见、可改、可回退的。

> 整改原则：**吸收孤海的采样质量，不牺牲我们的零偏移与可解释性。**

## 12. 产品目标与决策边界

**目标**：用户选一个预设、涂一笔遮罩、写一句话，结果符合直觉；不需要理解 A/B/native。

**允许自动（执行细节，不改变用户语义）**：

- 裁块大小 / 采样画布预算（1024² contain）
- 是否附加整图上下文（按指令类型）
- 提示词润色（可开关）

## 14. 验收口径（统一）

| 指标 | 门槛 |
| --- | --- |
| 遮罩外改动 | `outside_max_abs == 0`（硬门槛） |
| 输出尺寸 | 与源图完全一致 |
| 局部编辑有效性 | **遮罩内改动率** ≥ 阈值（删除/替换类建议 ≥ 60%）；`changed_ratio`（全图）只作参考，不能作判据 |
| 耗时 | 相对基线增幅 < 30% |
| 回归 | 矩阵 12 组中退化组数 = 0 |

> 为什么不用 `changed_ratio`：它按全图面积平均，小目标（徽章约占 0.04%~0.06%）删对了也只有 0.08% 左右，与"完全没动"在同一量级，无法区分。**遮罩内改动率** = 遮罩内被改动的像素数 / 遮罩像素数，删对了应接近 100%。
>
> 已实现：`align.changed_stats(..., inside_mask=)` 返回 `mask_changed_ratio`；`pipeline` 用**用户原始遮罩**计算（泄漏检查仍用膨胀后的过渡带遮罩），写入 `job.quality.mask_changed_ratio`；结果页徽标「遮罩内改动 x%」（≥60% 绿、<20% 黄），全图指标改名为「全图改动」并注明仅作参考。合成自检：16×16 遮罩全部改动时 `mask_changed_ratio=1.0` 而 `changed_ratio=0.062`，正是需要区分的两种情形。

### 15.1 已拍板

- **采样画布 1024² 的 15%~30% 耗时增幅：接受。** 编辑以完成任务为第一目标，预设效果不得低于原生；因此 M2 的验收门槛只保留"效果与零偏移"，不再把耗时作为否决条件。

### 15.2 已拍板：最小裁剪窗（替换"自动换整画布"方案）

**做法**：给裁块定一个**最小窗口尺寸**（候选 512 / 768 / 1024，默认 **1024**）。

- 先按遮罩包围盒 + 四向扩展系数算出窗口；
- 若窗口任一边小于阈值，则**以遮罩为中心把窗口扩到「阈值 × 阈值」**，扩出来的是真实周边像素，**不是放大**；
- 再夹到图像边界、32 对齐；超出画布的部分用边缘众数色补（沿用现有 `crop_with_color_fill`）；
- 之后仍受 `crop_max_side` 约束（大遮罩照样缩小）。

**为什么优于之前两个方案**：

| 方案 | 模型看到什么 | 问题 |
| --- | --- | --- |
| 现状（裁小块后放大） | 352×288 放大到 768×640 | 像素变多、信息没变多 |
| 之前的"小遮罩自动换 a/native" | 整图 | 慢，且 native 不保留遮罩外 |
| **最小裁剪窗（采纳）** | 1024² 的真实周边区域 | 有上下文、不放大、仍只贴回遮罩内 |

**默认值 1024 的理由**：与孤海九步工作流的 1024² 采样画布一致；此时小遮罩的采样画布天然就是 1024²，无需 contain 补边，也无需整图上下文。

**与预设的关系**：预设仍只定义任务语义；`crop_floor` 是执行参数，放在高级参数里（512/768/1024），用户显式选过就以用户为准。不涉及"改任务/改预设"。
