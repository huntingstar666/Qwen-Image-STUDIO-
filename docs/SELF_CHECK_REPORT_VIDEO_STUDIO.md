## 3. 参数与提示词注入核对

### 3.1 提示词装配顺序

```text
风格前缀
→ 本段使用资产的外观（按 refAssets → usedEntities → 台词命中 → 上一段继承）
→ 画面描述 description
→ 镜头语言 note
→ 用户指令 directive（去掉 @）
→ 画面质感 suffix
→ 负面词：默认 → 风格锁负面 → 本段负面
```

同一份 `used_entity_ids` 同时供三处使用，顺序不会错位：

- 最终提示词的资产顺序
- 图生图 `images[1..]` 的顺序
- LLM 读图时的「图N=某资产」映射

### 3.2 文生图 `/api/generate`

| 字段 | 值 |
|---|---|
| prompt | 装配后的最终提示词 |
| negative_prompt | 默认负面 + 风格负面 + 本段负面 |
| model | 项目生图模型（默认 qwen） |
| width / height | 按画布比例，最长边来自项目配置 |
| seed | seedBase + 镜头序号 × 97 + attempt × 13 |
| steps / cfg / turbo | 项目生图配置 |
| consistency_lora | 风格锁里配置了才带 |

### 3.3 图生图 `/api/edit`

| 字段 | 值 |
|---|---|
| images[0] | 图1：底稿 / 场景定场图 / 上一镜画面 |
| images[1..] | 图2、图3…：按 @ 与资产顺序排列的设定图 |
| prompt | 使用主项目识别的 `<image1>`、`<image2>` 标记 |
| size_mode | `follow`，不传 width/height |
| seed / steps / cfg / turbo / negative_prompt | 与项目配置一致 |
| model | 默认透传；若项目选的是 MOSS 则不传，交给主项目按 edit 选模型 |

### 3.4 资产文生图

- 不传 `images`，避免把分镜底稿带进去。
- 人物/道具 1024×1024，场景 1280×720。
- 提示词：风格前缀 + 资产名称/外观 + 设定图取景约定 + 风格后缀。
- 完成后自动加入资产参考图，最多保留 4 张。

## 4. 本次发现并修复的问题

### 4.1 图生图提示词没有使用 `<imageN>` 标记（高）

之前写的是「图1/图2」中文编号。单参考图时不容易暴露，多参考图时模型无法可靠绑定到实际输入图。已统一改为 `<image1>`、`<image2>`，与主项目 Web 编辑页一致。

### 4.2 场景名只认全名，导致场景卡丢失（高）

自检发现：场景卡登记「夜班车间」，台词写「走进车间」时匹配不到，最终提示词只剩人物外观。已修复：

- 场景名支持部分命中（≥2 字的最长片段）；
- 资产卡新增「别名」字段，角色可用「林工」「他」等称呼稳定命中；
- 别名只参与匹配，不进入最终提示词。

### 4.3 历史文件重启后顺序整体颠倒（中）

`_save_history` 写「最旧在前」，`_load_history` 却按「最新在前」反转读取，导致每重启一次历史列表方向翻转一次。已统一为文件「最新在前」，并补跨重启单测。

### 4.4 MOSS 模型被传给编辑通道（中）

项目生图模型若选 MOSS，图生图 payload 仍带 `model=moss`，而 MOSS 只支持文生图。已改为编辑通道不传 MOSS，由主项目按 `task=edit` 选择可编辑模型。

## 6. 已知边界与剩余风险

1. **场景部分命中可能误判**：极通用的两字片段可能命中不该命中的镜头；建议给场景补别名，或把名称写得更具体。
2. **长任务期间的并发编辑**：资产图/镜头图生成是「先读项目、生成、再保存」，生成期间若保存了设置，理论上可能被覆盖。当前为既有模式，后续可改为按实体合并写回。
3. **视觉润色需要空闲显存**：本地 `qwen2.5vl:7b` 与图像模型同时加载会 OOM；代码路径和消息构造已单测，实际使用需释放显存或使用云端视觉模型。
4. **导出渲染未在本轮重跑**：本轮重点检查参数/提示词/锚定/历史链路；渲染链路上次已验证，若需要可再做一次带图成片导出。
5. **参考图锚定默认关闭**：这是预期行为；打开后才会走单段或两段图生图。
